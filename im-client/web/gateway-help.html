网关部署使用教程

游戏联机加密隧道 / 积分赞助充值写库 / 带参启动免登录进游戏，按需选用 ｜ 支持 Windows 与 Linux 服务器（部署包已内含全平台程序，一次下载按系统选用）

一、网关是什么（三大用途，可只用其一）

用途 1：游戏联机加密隧道（端口转发）——玩家的 PC 客户端经网关的 TLS 加密隧道，连到你服务器 本机（127.0.0.1）的游戏服务端端口。你只需在配置里写一个监听端口和一组允许转发的本机端口白名单， 不需要数据库，联机数据全程加密转发。它带来的网络安全价值（防火墙只开一个端口、其余全部封闭）见 下一章详解。

用途 2：积分赞助充值写库——玩家在游戏内用积分向平台兑换游戏币：平台记录订单与扣分 → 你服务器上的网关按固定周期向平台拉取新订单 → 用参数化 SQL 把充值直接写进你的游戏数据库， 数据库账号无需对公网开放。

用途 3：带参启动，免登录进游戏——配合「游戏账号写库」：网关把玩家的 IM 账号与平台生成的 专属密码写入你的游戏库，玩家点开始游戏时平台按你配置的启动参数模板（{0}=账号、 {1}=专属密码）带参数拉起游戏客户端，玩家无需手动输入账号密码直接进游戏。 前提：你的游戏客户端须支持带账号/密码命令行参数启动（在游戏编辑页「启动程序 / 启动参数」里配置）。

三个用途互相独立、可只用其一：只用隧道联机，就不启用管理后台里的写库/充值（默认关闭）； 只用充值，监听与白名单按模板填你游戏的本机端口即可（网关要求至少一个监听组，不联机也无妨）； 要免登录进游戏，需启用「游戏账号写库」并在游戏编辑页配置带 {0}/{1} 的启动参数。 充值场景平台只下发「订单号 / 账号 / 金额」，不接触你的数据库密码以外的任何游戏数据； 写库 SQL 由你自己填写，平台无法越权操作你的库。

二、走隧道为什么更安全（网络安全详解）

传统开服要把游戏端口直接暴露在公网：玩家直连游戏端口，扫描器也扫得到你的游戏端口、数据库端口、 管理端口——任何一个服务有漏洞都可能被直接利用。走网关隧道后，架构变成 「玩家 → TLS 加密隧道（网关唯一入口）→ 127.0.0.1 本机端口」，安全模型彻底改变：

传统直连开服走网关隧道
公网必须开放的端口游戏端口（可能还有多个）仅网关 listen_tcp 一个
游戏服务端暴露直接暴露公网，可被扫描探测只绑 127.0.0.1，公网完全不可见
数据库端口可能被波及暴露与公网隔离，仅网关本机可达
联机流量明文（多数老游戏无加密）TLS 全程加密
能连到哪些目标端口开了就是全开仅 allow_targets 白名单内的 127.0.0.1 端口

具体是四层防护在起作用：

  1. 入口收敛：防火墙只放行网关的 listen_tcp 一个端口（listen_udp 配了不同端口则一并放行），游戏端口、数据库端口、远程桌面等全部对公网封闭——公网扫描器与攻击者只能看到网关一个入口，攻击面缩到最小；
  2. 目标白名单：网关只转发到 allow_targets 列出的 127.0.0.1 端口，白名单外一律拒绝——即使网关被盯上，也触达不了内网其他目标；
  3. 链路加密：玩家到网关全程 TLS（证书首次启动自动生成），账号密码与联机数据不在公网明文传输；
  4. 服务隐身：游戏服务端绑定 127.0.0.1（最安全），不监听公网网卡——不开放就等于不存在，扫描器探无可探。
一句话：公网只见一个门（网关），门后所有房间（游戏、数据库）都在内网里。 防火墙配置一句话——放行 listen_tcp，其余全封；游戏服务端监听地址改成 127.0.0.1 即可。

三、开始前：找平台管理员拿两样东西

需要说明
网关名由平台管理员在后台「网关地址簿」为你分配（小写字母/数字/_/-），后续填在游戏编辑的「充值网关名」里
专属密钥 token_secret同一条地址簿条目的 64 位十六进制密钥，填进网关配置文件——平台不会把密钥打进部署包，需单独向你提供

四、部署步骤

1

下载部署包并选用对应程序

商户后台 → 网关部署 → 「下载网关部署包（Windows + Linux）」。包内文件：

文件选用
im-gateway.exeWindows 10 / Server 2016 及以上（多数情况用这个）
im-gateway-2008r2.exeWindows Server 2008 R2 / 2012 专用兼容版
im-gateway-linuxLinux 服务器（amd64，静态编译零依赖，无需安装任何运行库）
im-gateway-linux-arm64Linux ARM 架构服务器（如有）
gateway.yaml配置模板（不含任何密钥），两端通用

按你的服务器系统选用对应程序即可，部署步骤见下文；Linux 部署另见「五、Linux 服务器部署」。

2

解压并填写 gateway.yaml

解压到任意目录（如 D:\im-gateway\），用文本编辑器打开 gateway.yaml， 改三处（写库 / 充值配置不在 yaml 里手填，见第 4 步的网关管理后台）：

listen_tcp: "0.0.0.0:30100"      # 隧道监听端口（联机用，可自定；TLS 证书首次启动自动生成）
allow_targets: [7777]            # 转发白名单：改成你游戏服务端在本机监听的端口（可多个）
admin_listen: "127.0.0.1:30101"  # 本机管理后台地址，保持仅内网
admin_password: "你的后台登录密码"     # 自行新增这一行：第 4 步登录管理后台用
token_secret: "管理员给你的64位密钥"   # 替换模板占位值！
dbwrite:
  poll_interval: 3s
  games: []                      # 保持为空即可，配置在第 4 步后台在线填写
allow_targets 是联机隧道的关键：只允许转发到你列出的 127.0.0.1 本机端口， 按你游戏服务端实际监听的端口填写（多个用逗号分隔，如 [7777, 7778]）。 admin_password 是管理后台登录密码（模板里没有这行，需自行新增），请使用强密码—— admin_listen 只能本机/内网访问，切勿绑定公网。
3

运行并放行端口

双击运行选定的网关程序（或命令行运行），并在服务器防火墙放行 listen_tcp 端口。 建议用 NSSM / 计划任务把它注册为系统服务，避免关掉命令行窗口后网关停摆。

只用隧道联机、不需要充值？到这一步就完成了——写库/充值默认关闭，无需再做第 4、5 步； 转发白名单以后可在管理后台在线调整（热生效）。
4

在网关管理后台在线配置写库 / 充值（只用隧道可跳过）

网关自带本机 Web 管理后台，写库与充值配置都在这里在线填写，保存即热生效并自动写回 gateway.yaml（无需手动改文件、无需重启）：

  1. 在网关所在服务器打开浏览器，访问 http://127.0.0.1:30101（即 gateway.yaml 的 admin_listen 地址），用第 2 步设置的 admin_password 登录；
  2. 「游戏账号写库」卡片：勾选启用 → 填自报网关名（与地址簿条目一致）和 im-server 地址 → 选数据库类型（连接串有默认模板，可点「测试连接」验证）→ 按提示改 INSERT/UPDATE 模板 → 「保存并热生效」。用途 3 的免登录进游戏依赖此卡片（把账号/专属密码写进游戏库）；
  3. 「积分兑换充值」卡片：勾选启用 → 填网关名与 im-server 地址 → 「+ 添加游戏」填游戏 ID、数据库类型、DSN 与充值 SQL 模板（占位符 {user}/{amount}/{order}）→ 「保存并热生效」。
页面内置了各数据库的连接串模板、TLS 老版本兼容（;encrypt=disable）、存储过程写法等完整提示， 照页面说明填写即可；复杂充值逻辑建议写在游戏库的存储过程里、按订单号 {order} 去重防重复加钱。
5

在游戏编辑页开启积分赞助

  1. 商户后台 → 我的应用 → 编辑游戏；
  2. 勾选「开放积分赞助」；
  3. 填写汇率（1 积分 = N 游戏币）、单日限额（0=不限）；
  4. 填写充值档位（逗号分隔，如 100,500,1000——档位即单笔白名单，不在档位内的金额无法充值）；
  5. 填写「充值网关名」（开始前平台管理员分配的网关名）→ 保存。
6

平台侧连通验证

通知平台管理员在后台「网关地址簿」确认本网关条目的地址/指纹正确并启用，由平台侧发起连通验证。 验证通过后玩家即可在游戏内使用积分赞助，充值自动写入你的数据库。

五、Linux 服务器部署（可选）

你的游戏数据库在 Linux 服务器上时，网关可以直接跑在 Linux 上（同一台机或同内网均可）。 网关是静态编译的单文件程序，零依赖——不需要安装 Go / 任何运行库，任何发行版直接运行。 部署包已内含 Linux 版 im-gateway-linux（ARM 服务器用包内 im-gateway-linux-arm64）， 无需另行索取，直接从包中取出使用即可。

1

上传并赋执行权限

用 scp / sftp（二进制方式）上传到服务器任意目录（如 /opt/im-gateway/）—— 切勿用文本模式 FTP，会损坏二进制导致 cannot execute binary file。然后执行：

chmod +x im-gateway-linux
file im-gateway-linux   # 显示 "statically linked" 即完整（x86-64=64位服务器；arm64 用 arm64 版）
2

准备 gateway.yaml

与 Windows 版第 2 步填法完全相同（同目录放一份：token_secret 填地址簿密钥、 自行新增 admin_password 一行、dbwrite.games 留空）。 配置文件两端通用，从 Windows 包里取模板改即可。

3

启动与常驻

前台试跑：./im-gateway-linux（须在 gateway.yaml 所在目录运行）。确认无报错后注册 systemd 常驻：

# /etc/systemd/system/im-gateway.service
[Unit]
Description=im-gateway
After=network.target

[Service]
WorkingDirectory=/opt/im-gateway
ExecStart=/opt/im-gateway/im-gateway-linux
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
systemctl daemon-reload && systemctl enable --now im-gateway
systemctl status im-gateway   # 查看运行状态与日志
4

防火墙与管理后台访问

  • 防火墙放行 listen 端口（firewalld：firewall-cmd --permanent --add-port=30100/tcp 后 reload；ufw：ufw allow 30100/tcp）；
  • admin_listen 只监听 127.0.0.1：远程访问走 SSH 隧道——本机执行 ssh -L 30101:127.0.0.1:30101 用户@服务器，然后浏览器开 http://127.0.0.1:30101 即可按「三、部署步骤」第 4 步的方式在线配置写库与充值。
其余步骤与 Windows 版完全一致：网关管理后台在线配置写库/充值 → 商户后台游戏编辑页开启积分赞助 → 平台侧连通验证。

七、安全须知

1. token_secret 泄露等同于放弃网关鉴权：请妥善保管，疑似泄露立即联系平台管理员在地址簿中轮换密钥（换后同步改 gateway.yaml 并重启网关）；
2. 写库数据库账号使用强密码 + 最小权限（只给目标表所需的 INSERT/UPDATE 权限）；
3. 网关机只放行 listen_tcp 端口（其余全部封闭，详见第二章）；admin_listen 保持 127.0.0.1，admin_password 使用强密码（管理后台可改写库配置，泄露等同开放数据库）；
4. 配置文件含数据库密码，注意服务器本身的访问控制与备份安全。

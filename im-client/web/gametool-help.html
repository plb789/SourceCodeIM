GamePatchTool 补丁工具使用教程

游戏增量更新：老玩家只下载变更文件（秒级更新），新玩家照常全量安装 ｜ 工具版本随服务端发布

一、补丁是什么

全量更新 = 玩家重新下载整个游戏（可能几十 GB）；补丁更新 = 玩家只下载有变化的文件（通常只有几 MB～几百 MB）。 你用本工具对比「已上架的旧版本」和「准备发布的新版本」，生成一个补丁包 patch.zip 上传即可。 补丁在服务器上会自动合成为完整的新版本——新玩家不受任何影响，照常安装完整版。

前提：基底版本（要打补丁的旧版本）必须是「散文件」或「补丁」方式上架的版本。单 ZIP / 分卷 ZIP 方式的版本无法打补丁（发布时请直接用全量包更新）。

二、准备工作

需要说明
gametool.exe本页顶部 / 商户后台"补丁包"模式里的「下载工具」按钮获取（Windows x64，无需安装）
新版游戏目录准备发布的完整新版游戏文件夹（所有文件放好，和平时上架前的目录一样）
基底版本清单商户后台 → 版本管理 → 目标旧版本行 → 点「导出清单」下载 filelist-版本号.txt

三、操作步骤

1

导出基底版本清单

商户后台 → 游戏管理 → 版本管理 → 找到要打补丁的旧版本（如 v1.0.0）→ 点「导出清单」， 得到 filelist-1.0.0.txt。这个清单记录了旧版本每个文件的 SHA256 校验值，是补丁的对比基准。

用清单而不是本地旧目录做基准，可以保证补丁和服务器上的版本精确对齐——你不需要保留旧版本地副本。
2

生成补丁包

打开命令行（在 gametool.exe 所在文件夹地址栏输入 cmd 回车），执行：

gametool diff -base-list filelist-1.0.0.txt -new D:\游戏新版目录 -out patch.zip -base 1.0.0 -ver 1.0.1
参数说明
-base-list第 1 步导出的基底版本清单文件
-new新版游戏的完整目录
-out输出的补丁包文件名（随便起，建议 patch.zip）
-base基底版本号（与清单对应的版本号一致，上传时要选它）
-ver补丁版本号（即你要发布的新版本号）
-list 新清单.txt可选：同时输出新版本的完整清单（留档核对用）

成功后会显示摘要，例如：

补丁已生成: patch.zip (18.32MB)
  变更/新增 12 个, 删除 3 个, 基准总量 14.62GB
  体积节省: 全量的 0.1%
如果显示「未检测到任何差异」，说明新版目录和服务器上的旧版本完全一致，不需要发补丁。
3

复检补丁（可选但推荐）

gametool verify -base-list filelist-1.0.0.txt -patch patch.zip

输出「复检通过」即可上传。能提前发现清单与补丁不匹配、路径非法等问题。

4

上传登记补丁版本

  1. 商户后台 → 版本管理 → 上传方式选「补丁包」；
  2. 基底版本下拉选择第 1 步的版本（如 v1.0.0）；
  3. 填写新版本号（与第 2 步 -ver 一致，如 1.0.1）；
  4. 选择 patch.zip → 「开始上传并登记版本」。

登记成功后玩家端即时生效：装过 v1.0.0 的玩家更新时只下载变更文件，未安装过的玩家下载完整新版本。

四、连续小更新（补丁链）

补丁可以叠加：v1.0.0 → 1.0.1 → 1.0.2…… 每次以「上一个版本」为基底即可。做法完全相同—— 在版本列表里对 v1.0.1 点「导出清单」，diff 后选基底 v1.0.1 上传。服务器会自动逐层合成，玩家从任何旧版本更新都能拿到正确结果。

五、其他命令

命令用途
gametool list -dir 目录 -out filelist.txt给任意目录生成清单（同款格式，可用于本地留档）
gametool diff -old 旧目录 -new 新目录 -out patch.zip离线模式：用本地旧目录代替清单做基准（无法联网时备用；推荐优先用清单模式）

六、常见错误对照

提示原因与解决
delete 路径不在基底版本清单中补丁里声明删除的文件在服务器旧版本里不存在——多半是基底版本选错了，或清单导出后又发过别的版本
patch.json change 与 zip 条目不一致补丁包被改动过或生成不完整——重新执行第 2 步生成
基底版本必须为散文件版或补丁版基底是「单 ZIP / 分卷 ZIP」方式上架的，无法打补丁——请发布全量包更新
补丁包解包失败 / 压缩包无法识别patch.zip 损坏（上传中断或传输损坏）——重新生成并上传
基底版本不存在选择的基底版本号在服务器上不存在（或已被删除）

七、注意事项

1. patch.json 是补丁包内的保留文件（工具自动生成），请不要手工改动或同名文件放入游戏目录；
2. 临时文件（*.tmp、~$* 开头）和空文件会被自动跳过，不会进入补丁；
3. 工具对比的是文件内容（SHA256），改了文件名但内容相同 = 旧路径删除 + 新路径新增；
4. 补丁只支持 ZIP 格式（工具自动生成），不支持加密压缩包；
5. 生成补丁前请确认新版目录是完整的——补丁只记录差异，缺失的旧文件不会自动补上（会当作"删除"处理）。

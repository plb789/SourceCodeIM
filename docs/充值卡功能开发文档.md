# 充值卡（卡密）功能开发文档（已确认·待实施）

> 状态：方案已确认（2026-11-03），未动代码。
> 关联文档：《积分兑换网关充值功能开发文档》（token 鉴权范式 §8 / 积分钱包与流水归口）、《网关开发文档》。
> 涉及代码：`im-server`（模型/生成/核销/导出/频控 + 管理接口）、`im-client/web/admin.html + js/admin.js`（管理端页）、`im-client/web/game-store.html + js/game-store.js`（客户端弹窗）。

## 1. 需求背景

管理员需要离线发放积分的载体：**按积分面值批量生成充值卡（卡号+卡密）并导出**（TXT/CSV/XLSX），玩家在 PC 游戏中心标题栏账号区弹出的充值页输入**卡号+卡密**核销，积分即时入账。卡密全生命周期可查：未使用/已使用/已作废、使用时间、使用者。

### 1.1 已拍板决策（2026-11-03）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 卡密存储 | **明文入库**（可按批次随时重新导出补发；数据库泄露则卡密泄露，内网库风险已评估接受） |
| 2 | 作废 | **需要**：未使用卡可作废；已使用/已作废不可再核销 |
| 3 | 字符集 | **字母数字混排**：卡密 16 位去易混淆字符（0/O/1/I/L 不用），卡号=前缀+12 位纯数字 |
| 4 | 入口范围 | **仅 PC 游戏中心**标题栏账号区（WEB/APP 同源代码自动继承），APP 不单独做页 |

## 2. 总体链路

```
管理端                        用户端（游戏中心标题栏账号区）
   │ ①生成(面值+数量+前缀)          │ ③输入卡号+卡密 → X-Drive-Token
   ▼                              ▼
im_recharge_card ──导出──▶ 管理员发卡  im-server 核销事务：
   (status=0 未使用)              │  · 条件更新卡 status 0→1（RowsAffected=1 唯一赢家）
                                  │  · 用户积分 += 面值
                                  │  · im_points_log(reason=card_recharge)
                                  ▼
                            ④返回新余额，标题栏刷新
```

要点：

- **与积分赞助（游戏币充值）链路完全独立**：卡密充的是用户积分余额，两者共用钱包（`users.points` + `im_points_log`），互不影响。
- **核销原子性**：核销与加分同事务，卡状态条件更新保证并发/重复提交下只有一次成功（双开、重放、连点均不可能双得）。
- **防爆破**：同账号 1 分钟内 5 次核销失败 → 临时锁 10 分钟（进程内存表，不落库）。

## 3. 各角色设计

### 3.1 im-server

#### 3.1.1 数据模型（`model` 包，AutoMigrate 自动建表）

**新表 `im_recharge_card`：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint64 主键 | |
| card_no | varchar(24) **uniqueIndex** | 卡号 = 管理员前缀（默认 `IM`，1~8 位字母数字）+ 12 位纯数字 |
| card_key | varchar(24) **uniqueIndex** | 卡密 = 16 位去易混淆字符字母数字（字符集 `23456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz`） |
| points | double | 面值（3 位小数口径，>0） |
| status | tinyint | `0` 未使用 / `1` 已使用 / `2` 已作废（单向迁移） |
| batch_no | varchar(32) 索引 | 批次号 `CR + yyyyMMddHHmmss`（同次生成归组） |
| created_by | varchar(64) | 生成管理员 |
| used_by / used_at | varchar(64) / datetime | 使用者 / 核销时间 |
| create_time | datetime | 生成时间 |

**状态机**：`0 未使用 → 1 已使用`（核销）/ `0 未使用 → 2 已作废`（管理端）；单向条件更新，终态不可逆。

#### 3.1.2 用户 API（资金接口，`guardRecharge` 同款 X-Drive-Token 强校验）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/game/card/redeem` | POST | Body `{card_no, card_key}`。链路：频控检查 → 卡存在（卡号+卡密联合查询）→ 事务【条件更新核销 `WHERE card_no=? AND status=0`（RowsAffected=1 才继续）→ 用户加分 → 流水】→ 返回到账面值与新余额。失败语义：卡号不存在/卡密不符（同一提示"卡号或卡密错误"，不区分防探测）、卡已使用、卡已作废、被频控锁定 |
| `/api/game/card/my` | GET | 本人卡密充值记录（从 `im_points_log` reason=card_recharge 取，无需新表查询）——可选，弹窗内"充值记录"复用 |

流水口径：`recordPointsLog(username, +points, after, "card_recharge", "system", "卡密充值: <card_no>")`。

**防爆破频控**（进程内存 `map[username]{failCount, lockUntil}` + 互斥锁）：1 分钟窗口内 ≥5 次失败 → 锁至 `now+10min`；核销成功清零。重启即清（可接受，频控是辅助，卡密空间 58^16 才是主防线）。

#### 3.1.3 管理端 API（`adminGuard` Bearer 鉴权）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/admin/api/game/card/generate` | POST | Body `{points, count, prefix}`。points>0（≤100000）、count 1~5000、prefix 1~8 位字母数字（默认 `IM`）。批量生成：卡密随机冲突自动重试（唯一索引兜底），同一事务批量插入；返回 `{batch_no, count, points}` |
| `/admin/api/game/card/list` | GET | `batch/status/page/size` 筛选分页，倒序；卡号/卡密明文回显（决策 1） |
| `/admin/api/game/card/void` | POST | Body `{ids:[]}`。条件更新 `status=0 → 2`，返回实际作废数（已使用/已作废自动跳过） |
| `/admin/api/game/card/export` | GET | `batch/format=txt\|csv\|xlsx`。流式下载（Content-Disposition 文件名含批次与时间）；txt 每行 `卡号,卡密,面值`；csv 带 UTF-8 BOM；xlsx 用 excelize 生成单表（表头+数据行）。单次导出上限 50000 行（防内存放大，超限按批次导） |

生成操作记管理审计日志（操作人/批次/数量/面值）。

#### 3.1.4 新增依赖

`github.com/xuri/excelize/v2`（纯 Go、零 CGO，符合项目约定；仅管理端导出使用）。

### 3.2 管理端 UI（im-client/web/admin.html + js/admin.js）

积分管理下新增"充值卡"二级页（nav `data-view="cards"`，section id **必须** `admin-view-cards` 与 data-view 一致——实测踩坑：不一致整页空白）：

1. **生成卡**（顶部卡片）：面值输入 + 数量输入 + 前缀输入（可空默认 IM）→ 自绘确认 → 生成成功 toast 显示批次号
2. **批次列表/筛选**：批次号/状态下拉/分页表格（`vec-table`，列：卡号、卡密、面值、状态、使用者、使用时间、生成时间）；行选择或按批次整组导出
3. **导出按钮组**：TXT / CSV / XLSX（当前筛选范围）；**作废**按钮（选中未使用行，自绘确认）
4. 全部走现有 `api()`（Bearer 自动携带），无系统弹窗，主题变量取色

### 3.3 客户端 UI（im-client/web/game-store.html + js/game-store.js）

**入口**：游戏中心标题栏账号区（头像/昵称/余额展示处）加"卡密充值"入口（点击弹出，仅登录态显示）。

**充值弹窗**（自绘，无系统弹窗，跟随主题色，Steam"兑换码"风格）：
- 卡号输入框 + 卡密输入框（卡密可切换明文/掩码）
- 提交 → 自绘确认 → `POST /api/game/card/redeem`
- 成功：toast"充值成功，到账 N 积分，当前余额 M"+ 标题栏余额即时刷新（`state.balance`）
- 失败：toast 服务端 msg（卡号或卡密错误/卡已使用/卡已作废/尝试过于频繁）
- 弹窗内附"积分赞助"跳转链接（同一钱包两种充值方式互导流）

i18n：zh-CN 为 key 原文，en-US 补词条。

## 4. 安全设计汇总

| 风险 | 对策 |
|------|------|
| 并发重复核销双得 | 事务内条件更新（`WHERE status=0`，RowsAffected=1 唯一赢家）+ 唯一索引 |
| 冒名核销他人积分 | `guardRecharge` 同款 X-Drive-Token 强校验（自报 username 须与 token 归属一致） |
| 卡密爆破 | 卡密空间 58^16（主防线）+ 同账号失败频控（1 分钟 5 次锁 10 分钟）+ 统一错误文案（不区分卡号/卡密错误，防探测） |
| 导出泄露 | adminGuard Bearer；导出动作记管理审计日志；文件名含批次不含用户数据 |
| 明文库泄露 | 已拍板接受（决策 1）；后续可升级哈希存储（仅生成时一次性导出） |
| 管理端误操作 | 作废仅限未使用卡 + 自绘二次确认；生成单批上限 5000 |
| XSS | 卡号/卡密字符集白名单（字母数字），管理端列表/导出均无用户可控 HTML |

## 6. 验收清单

- [ ] 生成：面值/数量/前缀生效，卡号卡密唯一、字符集正确（无 0O1IL），批次号归组
- [ ] 单批 5000 张上限拦截；points≤0 拒绝
- [ ] 导出：TXT/CSV/XLSX 三格式内容与筛选范围一致，CSV Excel 打开中文不乱码
- [ ] 核销：到账精确、流水 reason=card_recharge、余额实时刷新
- [ ] 并发双开同一卡仅一人成功（另一人收到"卡已使用"）
- [ ] 已使用/已作废卡核销拒绝；作废仅对未使用卡生效
- [ ] 无 token / 伪造 token → 401；频控：5 次失败后锁 10 分钟
- [ ] 客户端：弹窗自绘无系统控件、主题色跟随、成功后标题栏余额即时刷新
- [ ] 回归：全量套件通过，积分赞助/商店购买/积分红包/AI 扣费不受影响

## 1. 现状诊断

### 1.1 已有基础（可复用）

| 组件 | 现状 |
|---|---|
| `Merchant` 模型 | ✅ 有 `CommissionRate`（分成比例，默认 100%），但**无余额/收入/提现字段** |
| `Game.OwnerUsername` | ✅ 游戏归属商户（空=官方） |
| 入库扣费 | ✅ `HandleGameLibraryJoin` 扣用户积分 + 写 `game_purchase` 流水，但**积分直接归零，不分给商家** |
| 移出退款 | ✅ `HandleGameLibraryLeave` 退用户积分 + 软删除，但**退款不扣商家收益** |
| 退款超期 | ✅ `refund_days` 配置，超期不退积分（商家白拿） |
| 商家后台 | ✅ 有 `merchantGuard` + profile + 赞助充值统计（仅看自己的 `recharge_order` 聚合） |

### 1.2 断点清单（本次要补）

| 断点 | 说明 |
|---|---|
| ① **入库积分无去向** | 用户 `game_purchase` 扣的积分直接归零（reason=system），不分给商家 |
| ② **商家无收益账本** | 商家看不到"我卖了多少积分"，没有可提现余额 |
| ③ **退款商家不扣回** | 用户退款是平台全额承担（game_refund 流水），商家收益不扣减 |
| ④ **无提现链路** | 没有提现申请单、审批、出账流程 |

### 1.3 当前入库链路（无分账）

```
用户 POST /api/game/library/{id}
 │
 ├─ ① 扣用户积分 UPDATE users SET points = points - pay  WHERE points >= pay
 ├─ ② 写 game_purchase 流水（用户扣分 -pay）
 ├─ ③ CREATE im_game_library
 └─ 结束 ❌ 积分直接归零，商家没拿到
```

## 2. 设计目标

1. **入库分账**：用户付费后，按 `commission_rate` 把商家应得积分计入商家余额（余额=可提现）
2. **退款扣回**：用户退款时（超期内），同步从商家余额扣回；超期不退的保留商家收益
3. **锁定期**：商家余额有 X 天锁定（类似 Steam 钱包余额），防止玩家退款窗口内商家提走
4. **商家查看**：商家后台看总余额、待结算（锁定中）、可提现、累计收益、分账明细
5. **提现流程**：商家提交提现 → 管理员审批 → 扣商家余额（积分不做真实出款，按内部口径记账）

## 4. 表结构扩展

### 4.1 Merchant 表增量（ALTER TABLE 自动完成）

```sql
ALTER TABLE im_merchant
  ADD COLUMN balance_points   DOUBLE NOT NULL DEFAULT 0 COMMENT '可提现余额（已过锁定期）',
  ADD COLUMN pending_points    DOUBLE NOT NULL DEFAULT 0 COMMENT '待结算（锁定期内）',
  ADD COLUMN total_earned     DOUBLE NOT NULL DEFAULT 0 COMMENT '累计总收益（含已提现）',
  ADD COLUMN total_refunded   DOUBLE NOT NULL DEFAULT 0 COMMENT '累计退款扣回',
  ADD COLUMN total_withdrawn  DOUBLE NOT NULL DEFAULT 0 COMMENT '累计已提现';
```

字段说明：
- **balance_points**：商家当前可提。入库分账时先加 pending_points，到期自动转 balance_points
- **pending_points**：正在锁定。退款窗口内的收益，超期自动解锁
- **total_earned**：累计历史，统计用
- **total_refunded**：累计被退款扣回，统计用
- **total_withdrawn**：累计已提现，对账用

### 4.2 新建表：im_merchant_income_log（收益流水）

```sql
CREATE TABLE im_merchant_income_log (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  merchant     VARCHAR(32) NOT NULL COMMENT '商户账号',
  game_id      BIGINT      NOT NULL COMMENT '游戏 ID',
  username     VARCHAR(32) NOT NULL COMMENT '付费用户',
  purchase_id  BIGINT      NOT NULL COMMENT '关联 GameLibrary.ID',
  user_pay     DOUBLE      NOT NULL COMMENT '用户实付积分',
  commission   DOUBLE      NOT NULL COMMENT '商家分成比例（0~1）',
  merchant_earn DOUBLE     NOT NULL COMMENT '商家本次应得分账（commission * user_pay）',
  type         TINYINT     NOT NULL COMMENT '1=入库分账 2=退款扣回 3=提现扣减 4=手动调整',
  status       TINYINT     NOT NULL COMMENT '1=pending 锁定中 2=settled 已解锁 3=refunded 已扣回',
  settle_time  DATETIME    NULL     COMMENT '预计/实际解锁时间',
  create_time  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant),
  INDEX idx_type_time (type, create_time)
) COMMENT '商家收益流水';
```

### 4.3 新建表：im_merchant_withdraw_order（提现申请单）

```sql
CREATE TABLE im_merchant_withdraw_order (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  merchant     VARCHAR(32) NOT NULL,
  points       DOUBLE      NOT NULL COMMENT '申请提现积分',
  status       TINYINT     NOT NULL COMMENT '0=pending 1=approved 2=rejected',
  reject_reason VARCHAR(255) DEFAULT '',
  operator     VARCHAR(32) DEFAULT '' COMMENT '审批管理员',
  remark       VARCHAR(255) DEFAULT '' COMMENT '商家备注（提现到哪、联系方式等）',
  audit_time   DATETIME    NULL,
  create_time  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_merchant (merchant),
  INDEX idx_status (status)
) COMMENT '商家提现申请单';
```

### 4.4 定时任务表（无需新表）

锁定期到期自动把 pending → balance 用定时任务扫，不配新表。

## 5. 核心链路

### 5.1 入库分账（HandleGameLibraryJoin · 付费首次入库）

```
事务 BEGIN
  ├─ ① 扣用户积分 UPDATE users SET points = points - pay
  │     WHERE username = ? AND points >= pay
  ├─ ② CREATE im_game_library
  ├─ ③ 分账（仅当 pay > 0 AND game.owner_username != ''）：
  │     merchant_earn = ROUND(pay * commission_rate, 3)
  │     UPDATE im_merchant SET
  │       pending_points = pending_points + merchant_earn,
  │       total_earned   = total_earned   + merchant_earn
  │     WHERE username = game.owner_username
  ├─ ④ CREATE im_merchant_income_log
  │     (type=1, status=1[pending], settle_time = NOW + refund_days)
  └─ ⑤ recordPointsLog 用户 game_purchase
     （商家流水独立表，不走用户积分钱包流水）
事务 COMMIT
```

### 5.2 移出退款（HandleGameLibraryLeave · 退款期内）

```
事务 BEGIN
  ├─ ① 软删除 game_library + 标记 pay_refunded=true
  ├─ ② 退用户积分（现有逻辑）
  ├─ ③ 商家扣回：
  │     a. 按本次 purchase_id 查 income_log（type=1 对应本次分账）
  │     b. 找到对应 merchant_earn
  │     c. 先扣 pending_points（锁定中）：
  │        UPDATE im_merchant SET
  │          pending_points = GREATEST(pending_points - merchant_earn, 0),
  │          total_refunded = total_refunded + 扣回额
  │        WHERE username = ? AND pending_points >= merchant_earn
  │     d. 若商家余额不足（极端场景），回退扣 balance_points
  │     e. income_log UPDATE status=3 refunded
  └─ ④ recordPointsLog 用户 game_refund
事务 COMMIT
```

### 5.3 移出·超期不退（商家收益保留）

```
软删除 game_library + pay_refunded=false
income_log 保持 status=1 pending，到期自动解锁到 balance_points
不分账变更（商家白拿，符合 Steam 同款"退款窗口过了钱就是我的"）
```

### 5.4 锁定期到期（定时任务）

```
每 5 分钟扫 income_log：
  WHERE status = 1 AND settle_time <= NOW

UPDATE im_merchant SET
  pending_points = GREATEST(pending_points - merchant_earn, 0),
  balance_points = balance_points + merchant_earn
WHERE username = ?

UPDATE income_log SET status = 2 WHERE id = ?
```

### 5.5 提现申请（商家提交）

```
校验：points > 0 AND points >= min_withdraw_points AND balance_points >= points
事务 BEGIN
  ├─ ① UPDATE im_merchant SET
  │     balance_points = balance_points - points,
  │     total_withdrawn = total_withdrawn + points
  │   WHERE username = ? AND balance_points >= points
  ├─ ② INSERT withdraw_order status=0 pending
  └─ ③ INSERT income_log type=3 status=3
事务 COMMIT
```

### 5.6 提现审批（管理员）

```
approve：状态置 1 approved（积分已扣，审批=确认）
reject：
  事务 BEGIN
    ├─ ① UPDATE im_merchant SET
    │       balance_points = balance_points + points,
    │       total_withdrawn = GREATEST(total_withdrawn - points, 0)
    │     WHERE username = ?
    ├─ ② UPDATE withdraw_order SET status=2, reject_reason=?, operator=?
    └─ ③ INSERT income_log type=4 status=2（反向冲回）
  事务 COMMIT
```

## 8. 事务边界 & 并发安全

| 链路 | 事务 | 关键点 |
|---|---|---|
| 入库分账 | **全事务** | 扣用户→写库→加商家 pending→写 income_log，任一失败整体回滚 |
| 退款扣回 | **全事务** | 软删库→退用户→扣商家 pending→写 income_log 负向，整体 |
| 锁定期到期 | 单条 UPDATE | 定时任务串行，零并发冲突 |
| 提现申请 | **全事务** | 扣商家 balance→写 withdraw_order→写 income_log，整体 |
| 提现审批拒绝 | **全事务** | 回滚商家 balance→改 withdraw_order 状态，整体 |
| 提现审批通过 | 单条 UPDATE | 扣减已发生（申请时就扣了），审批=确认，无回滚 |

并发保护：
- 入库分账：GameLibrary uniqueIndex + 事务内加行锁，同一用户同一游戏不会双入库
- 退款扣回：income_log UPDATE WHERE merchant_earn 条件，同一 purchase 不会双扣
- 锁定期到期：定时任务按 `status=1 LIMIT 100` 分批，单条 UPDATE 天然并发安全
- 提现申请：`WHERE balance_points >= points` 并发不透支（Raft 语义同用户积分扣费范式）

## 9. 边界场景矩阵

| 场景 | 预期行为 |
|---|---|
| ① 用户免费入库（price=0） | 不分账，商家收益流水不写 |
| ② 用户官方游戏入库（owner 空） | 不分账，无 owner 跳过分账逻辑 |
| ③ 商家停用（status=1）但仍有在售游戏 | 照常有收益（历史分账不中断）；提现审批时可选择拒绝 |
| ④ 用户移出库·超期不退 | 商家 pending 到期自动转 balance，白拿 |
| ⑤ 用户移出库·退款期内 | 商家 pending 扣回，流水标记 refunded |
| ⑥ 商家把 pending 提了（不可能） | pending 不在 balance 里，前端只展示 balance；提现接口只认 balance |
| ⑦ 商家余额不足退款（极限） | 方案 C：扣到 0 为止，用户仍全额退，平台垫 |
| ⑧ 商家被管理员删除 | 不影响历史 income_log（保留对账）；有 pending 余额需先清零 |
| ⑨ 定时任务扫到已下线商户 | 仍处理 unlock（钱该给还是给，商户停用只影响前台） |

## 11. 风险 & 降级

| 风险 | 降级策略 |
|---|---|
| 数据库字段未就位就进代码 | AutoMigrate 自动加列，启动时即完成，存量商户字段默认值 0，零回归 |
| 分账链路 bug 导致用户入库成功但商家没加钱 | 账本兜底：可通过 merchant_income_log 补记，按 user_pay * commission 回填 |
| 商家恶意提现后退款（方案 C 平台垫损） | 平台垫损范围 = 用户付费 × (1 - commission_rate)，平台只承担分成以内的比例 |
| 锁定期定时任务挂了 | 重启自动恢复；income_log.settle_time 作为唯一解锁锚点，不丢账 |
| 商家余额变负数（并发+极端场景） | 方案 C 已用 GREATEST(balance - x, 0) 钳零，不会出现负 |

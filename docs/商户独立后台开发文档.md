# 商户独立后台功能开发文档（已确认·待实施）

> 状态：方案已确认（2026-11-04 拍板），未动代码。
> 关联文档：《积分兑换网关充值功能开发文档》（充值订单/网关归口）、《充值卡功能开发文档》（鉴权与积分钱包范式）。
> 涉及代码：`im-server`（模型/商户鉴权/游戏归属与审核/统计/网关包下发）、`im-client/web/merchant.html + js/merchant.js`（商户后台·新增）、`im-client/web/admin.html + js/admin.js`（商户管理+游戏审核·增量）、`im-client/web/js/game-store.js`（玩家侧展示过滤·微调）。

## 1. 需求背景

平台开放游戏入驻：商户（游戏发行方）在**独立后台**自助完成新增游戏、发布公告、上传游戏客户端与版本更新；玩家在其游戏内赞助充值（积分兑换游戏币）的数据对商户可见（含平台抽成后的应结金额）。商户提交的游戏须经**管理员审核**通过后才显示到玩家前端。商户页面同时提供**网关部署包**（`im-gateway.zip`，含 Windows 标准版 / 2008R2 兼容版 / Linux 版程序）下载与部署引导。商户后台 UI 采用与游戏中心一致的 Steam 风格。

### 1.1 已拍板决策（2026-11-04）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 商户账号 | **管理员创建**（不开放自助注册）：后台"商户管理"页建账号（=IM 账号体系，role=2），可启停/重置密码/调整分成比例 |
| 2 | 充值数据 | 商户可见**自己名下游戏的玩家赞助积分总额（仅成功单）**，并显示**分成/结算比例**与**平台抽成后应结金额**（比例由管理员按商户设置，应结金额服务端计算，前端只展示） |
| 3 | 充值配置 | 商户可自配自己游戏的**汇率/档位**（沿用 recharge_rate/recharge_tiers 字段），管理员保留**终审修改权**（随时可改，以后台为准） |
| 4 | 版本审核 | **版本不需要过审**：游戏过审后商户上传新版本/更新直接生效 |
| 5 | 网关包 | 所有商户下载**同一通用包**（exe + gateway.yaml 模板 + 部署说明，**不含任何密钥**） |
| 6 | 存量游戏 | 全部归官方（owner 空，商户不可见不可改），管理员后台不受影响 |

## 2. 总体架构

```
商户（role=2）                    管理员（role=1）                    玩家端
   │ merchant.html/js               │ admin.html/js（增量）              │
   │ ①登录 Bearer(im:merchant:token) │ ⑤商户管理：建号/启停/比例           │
   │ ②新增/编辑游戏 ──audit=1──┐     │ ⑥游戏审核：通过(audit=2+上架)/驳回   │
   │ ③公告/版本上传(归属校验)   │     │ ⑦可代改一切字段(含汇率/档位/比例)    │
   │ ④赞助统计+网关包下载       ▼     ▼                                   ▼
   │              im_game(owner_username + audit_status) ──仅 audit∈{0,2}──▶ 商店/详情
   └────────────── im_recharge_order(按 owner 聚合, 只读) ──▶ 分成/应结金额
```

要点：

- **数据隔离归口**：商户全部接口服务端强制 `owner_username = 当前商户`（SQL 层隔离，不靠前端隐藏）；slug 全局唯一保留（防商户间安装目录冲突）。
- **审核墙**：玩家侧游戏列表/详情/区块/置顶等聚合查询统一追加 `audit_status IN (0,2)`（0=官方免审，存量零回归）；商户侧可见自己全部状态的游戏。
- **版本不过审**（拍板 4）：游戏过审后版本操作直接生效；游戏未过审（audit=1/3）时其版本对玩家不可见（被游戏层过滤天然覆盖）。

## 3. 各角色设计

### 3.1 数据模型（`model` 包，AutoMigrate 自动加列/建表）

**新表 `im_merchant`（商户资料/配置）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uint 主键 | |
| username | varchar(32) **uniqueIndex** | 商户账号（=users.username，role=2） |
| name | varchar(64) | 商户显示名 |
| commission_rate | double | 商户分成比例（0~100，默认 100=全额；应结=成功总额×rate% |
| status | tinyint | 0 启用 / 1 停用（停用后登录拒绝，游戏对玩家隐藏？否——已过审游戏保留展示，仅禁登录，见 §5） |
| remark | varchar(255) | 备注（管理员可见） |
| create_time / update_time | datetime | |

**`Game` 表加列（存量自动补默认值零回归）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| owner_username | varchar(32) index，default '' | 归属商户（空=官方游戏） |
| audit_status | tinyint default 0 | `0` 官方免审 / `1` 待审核 / `2` 已通过 / `3` 已驳回 |
| audit_remark | varchar(255) default '' | 驳回理由（商户端可见） |
| audit_time | datetime null | 最近审核时间 |
| audited_by | varchar(32) default '' | 审核管理员 |

**审核状态机**：`商户新增/编辑对外字段 → 1 待审核`；`1 → 2（通过，status 自动置 0 上架）/ 1 → 3（驳回+理由）`；`3 → 改后重新提交 → 1`。管理员创建的游戏 owner 空 audit=0 永不经审；管理员可随时改任何游戏（含代商户改，代改对外字段也回待审核）。

**复用不改表**：`GameVersion`（版本上传/更新）、`GameNotice`（公告）、`im_recharge_order`（充值订单）、`users`（role 加 2=商户）。

### 3.2 im-server：商户鉴权归口（新文件 `server/merchant.go`）

- `POST /api/merchant/login`：username+password → `verifyUser` + `role=2` + 商户 status=启用 → 签发 Bearer（Redis `im:merchant:token:{tk}` = username，与 adminGuard 同款机制、独立键前缀，1 小时滑动续期）
- `merchantGuard(handler)`：Bearer → username → 再查 role=2 与启用状态（防改角色后旧 token 残留）→ ctx 注入；所有 `/api/merchant/*` 经此
- 归属校验辅助 `merchantOwnGame(username, gameID)`：查 `im_game` owner_username 匹配，不匹配一律 404（不暴露存在性）

### 3.3 im-server：商户接口清单（`server/merchantgame.go`）

| 接口 | 说明 |
|------|------|
| GET /api/merchant/profile | 资料 + 分成比例（应结展示参数） |
| GET /api/merchant/games | 自己的游戏（含各审核状态/驳回理由/版本数） |
| POST /api/merchant/games | 新增游戏：清洗复用 `rechargeGameCfgClean` 同款；slug 唯一校验；入库 audit=1；**汇率/档位可自配**（限本游戏 recharge_enabled/rate/tiers/网关绑定） |
| PUT /api/merchant/games/{id} | 编辑：对外字段（名称/简介/封面/截图/标签/价格/汇率/档位）→ 改后 audit 回 1；运营字段（联机端口/存档路径/NetMode 等）拒绝（管理员专属） |
| POST /api/merchant/games/{id}/status | 上架（仅 audit=2 可）/下架（随时） |
| GET/POST/PUT/DELETE /api/merchant/notices | 公告 CRUD（复用 GameNotice，全部经归属校验） |
| GET /api/merchant/games/{id}/versions | 版本列表 |
| POST /api/merchant/version/* | 版本上传：**复用现有 8MB 分片 + SHA-256 + finish 合并链路**，分片口加 merchantGuard 与 game_id 归属校验；版本不过审直接生效；登记即最新（冗余自动刷新），可删除 |
| GET /api/merchant/recharge/summary | 赞助统计：成功单积分总额（按游戏/按日聚合）× 分成比例 → 应结金额；处理中/失败不计入 |
| GET /api/merchant/recharge/orders | 自己名下游戏的充值订单（只读，分页+筛选） |
| GET /api/merchant/gateway/package | 网关包下载（见 §3.5） |

### 3.4 im-server：管理端增量（`server/merchantadmin.go` + gameadmin 增量）

| 接口 | 说明 |
|------|------|
| GET/POST /admin/api/merchants | 商户列表/创建（建 users 行 role=2 + im_merchant 行，密码 bcrypt 归口 hashPassword） |
| PUT /admin/api/merchants/{username} | 改显示名/分成比例/启停/重置密码 |
| GET /admin/api/merchant/audit/list | 审核列表（audit=1 优先，含商户提交时间） |
| POST /admin/api/merchant/audit/{id} | 通过（audit=2 + status=0）/驳回（audit=3 + remark）。挂 merchant 字面量前缀防与既有 {id}/version 两可匹配 panic |

管理员既有游戏编辑接口不动（全量可见可改）；商户创建的挂 owner 后管理员代改对外字段同样回待审核。

### 3.5 网关包下发（`server/merchantgateway.go`）

> 2026-11-08 更新：包升级为**多平台一次下载**，包名与缓存路径同步变更。

- 包内容（缺哪个二进制跳哪个，缺失时服务端记 Warn 提示补齐）：
  `im-gateway.exe`（Windows 标准版）+ `im-gateway-2008r2.exe`（2008R2/2012 兼容版，Go1.20 构建）+
  `im-gateway-linux`（Linux amd64 静态版）+ `im-gateway-linux-arm64`（ARM 版，构建了才收录）+
  `gateway.yaml`（**模板，不含 token_secret/商户密钥**）+ `部署说明.txt`（双平台部署速览）
- 首次请求打包 zip 缓存至 `LocalDir/gateway/im-gateway.zip`，之后直接流式下发（Content-Disposition attachment）；
  任一源二进制 mtime 比 zip 新时自动重建
- `merchantGuard` 校验通过才可下载；产物全缺返回明确错误提示（提示管理员预置产物）
- 图文部署教程：`web/gateway-help.html`（商户后台「使用说明」按钮打开）

### 3.6 玩家侧展示过滤（唯一存量链路改动点）

游戏列表/详情/推荐区块/置顶/搜索等聚合查询统一追加 `audit_status IN (0,2)`（与现有 `status=0` 上架条件并列）；存量官方游戏 audit 默认 0 零回归。评测/库内动态等按 game_id 关联处天然继承（游戏不可见即入口不可达）。

## 4. 前端设计

### 4.1 商户后台（新增 `merchant.html` + `js/merchant.js`）

- **登录页**：自绘表单（无系统弹窗），Bearer 存 localStorage（`im_merchant_token`），401 统一跳登录
- **面板布局**：左侧导航（我的游戏 / 新增游戏 / 公告管理 / 版本管理 / 赞助统计 / 网关部署），Steam 风格——全部颜色引用 `style.css` 现有主题变量、复用 game-store 卡片流/弹窗/Toast/自绘悬浮滑块（`.osb-thumb`），主题跟随 `im_theme`
- **我的游戏**：卡片列表（封面+审核状态徽标：待审核黄/已通过绿/已驳回红+理由气泡）+ 上架/下架开关
- **新增/编辑游戏**：表单复用 admin 游戏表单精简版（基础信息+封面截图上传+汇率/档位/网关绑定）；编辑已过审游戏时提示"保存后需重新审核"
- **版本管理**：按游戏选游戏 → 版本列表 + 分片上传（进度条复用 admin 上传组件逻辑）+ 设为最新/删除
- **赞助统计**：汇总卡（成功总额 / 分成比例 / 应结金额）+ 按游戏/按日明细表 + 订单只读列表
- **网关部署**：下载按钮 + 部署步骤说明

### 4.2 管理后台增量（admin.html/admin.js）

- 新视图"商户管理"：商户列表（账号/显示名/分成比例/状态/游戏数/累计赞助）+ 创建/编辑弹窗（启停、重置密码、比例 0~100 校验）
- 新视图"游戏审核"：待审核队列 + 游戏 prefill 预览 + 通过/驳回（驳回必填理由）
- 游戏管理现有列表加"归属/审核状态"列与筛选；编辑表单加审核操作快捷按钮
- `admin.js` 版本号提升强制刷新

### 4.3 玩家端

仅服务端过滤生效，前端零改动（被驳回/待审核游戏不出现在任何列表与详情入口）。

## 5. 安全设计

| # | 风险 | 对策 |
|---|------|------|
| 1 | 商户横向越权（看/改他人游戏、订单） | 全部商户接口 SQL 层 `owner_username` 强制过滤；不匹配返回 404 不暴露存在性 |
| 2 | 未过审游戏泄露 | 玩家侧所有聚合查询统一 `audit_status IN (0,2)`；详情接口同样过滤（直连 ID 不可达） |
| 3 | 商户提权/越界字段 | 商户接口字段白名单清洗：运营字段（联机/存档/NetMode/owner/audit）拒绝写入；merchantGuard 每请求回查 role=2 + 启用状态 |
| 4 | 上传滥用 | 复用现有分片校验（SHA-256/清单上限/大小上限）+ 归属校验前置；商户上传与官方同目录规范（`/static/upload/games/`） |
| 5 | 应结金额篡改 | 分成比例仅管理员可改、服务端计算，商户接口只读返回 |
| 6 | 网关包泄露风险 | zip 仅含公开 exe 与**无密钥** yaml 模板；密钥仍走后台 GatewayBook 单独配置 |
| 7 | 会话安全 | 商户 token 独立键前缀，与 admin 会话互不通用；停用商户即刻拒登（token 回查） |
| 8 | 注入 | 全程 GORM 参数化；slug 格式白名单沿用现有校验 |

> 拍板补充：商户被停用后其已过审游戏**保留对玩家展示**（玩家资产/充值链路不中断），仅禁止商户登录操作；如需连旗下游戏一并隐藏，由管理员对该游戏手动下架即可。

## 6. 分期计划

- **P1 服务端**：模型（im_merchant / Game 加列 / users.role=2）+ merchantGuard + 登录 + 游戏 CRUD（审核状态机）+ 管理端商户管理/审核接口 + 玩家侧过滤 + 单测（鉴权/越权/审核流转/过滤）
- **P2 前端**：merchant.html/js 全套（Steam 风格）+ admin 商户管理与游戏审核视图 + 公告/版本上传归属校验联调
- **P3**：赞助统计 + 网关包打包下发 + E2E（商户建游戏→审核→上架→玩家可见→充值→统计口径）+ 测试报告 + 全量回归

## 7. 验收清单

- [ ] 商户登录：仅 role=2 + 启用可登录；停用后 token 即失效
- [ ] 商户新增游戏 → 待审核；玩家端任何入口不可见；管理员通过 → 玩家可见且自动上架
- [ ] 驳回含理由，商户可见并重新提交
- [ ] 商户编辑自己游戏对外字段 → 回待审核；审核期间已入库玩家保留详情与游玩（旧内容），新玩家发现面（列表/区块/置顶）不可见
- [ ] 商户仅能看到/操作自己名下游戏、公告、版本、订单（横向越权 404）
- [ ] 版本上传走分片链路，SHA-256 校验通过，版本更新玩家端即时可见（游戏已过审前提下）
- [ ] 商户可自配汇率/档位；管理员可改并覆盖
- [ ] 赞助统计：成功单总额、比例、应结金额口径正确；处理中/失败不计入
- [ ] 网关包可下载且 zip 内无任何密钥；2008R2 机器按说明可部署连通
- [ ] 存量官方游戏：owner 空、audit=0，管理后台与玩家端行为与现在完全一致（零回归）
- [ ] 全量回归（server/gateway）通过，新增用例全绿

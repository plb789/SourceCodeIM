# APP / PC 客户端自动更新使用说明

> 服务端版本归口：`im-server/server/appversion.go`（阶段二百六十）
> 后台入口：管理后台 → 左侧导航 **[客户端更新]**
> 检查接口（公开只读）：`GET /api/app/version?platform=android|win&...`

## 一、总体机制

| 端 | 更新对象 | 版本比对依据 | 更新方式 |
|---|---|---|---|
| APP（Android） | APK 原生壳 | `versionCode`（整型，必须递增） | 检查 → 下载 APK（SHA256 校验）→ 拉起系统安装页 |
| PC（Windows） | Setup 安装包 | `version_name`（语义化 x.y.z，semver 比较） | electron-updater 全自动下载 → 重启安装 |
| WEB 浏览器 | 无壳更新 | — | 部署 `im-client/web/` 文件即时生效，不走本流程 |

要点：
- **上传 ≠ 发布**：后台上传安装包后版本默认"未生效"，必须点 **[启用]** 才对外下发（同平台仅一个生效版本，启用新版自动停用旧版）。
- **强制更新**：上传时勾选 force，客户端弹窗不可关闭、必须更新后才能继续使用。
- 此处仅用于**原生壳变更**（新权限、插件、打包资源）；界面/功能改动直接部署 web 文件即可。

## 二、APP 端（Android APK）发布流程

### 1. 修改版本号

文件：`im-client/app/android/app/build.gradle`（defaultConfig 节，约 17-18 行）

```groovy
versionCode 2          // 整型，每次发版必须 +1（或更大），绝不能回退/重复
versionName "1.1"      // 展示用版本名，可自由命名
```

> 注意：已安装 versionCode=N 的设备，安装 versionCode≤N 的包会被 Android 拒绝；
> APP 端检查更新按 versionCode 整型比对，忘记加 versionCode 是最常见事故
> （客户端永远收不到更新提示，或后台填的值与 APK 实际值不一致导致反复提示）。

### 2. 编译 APK

双击运行：`im-client/app/一键编译APK.bat`

流程：JDK17（工程内 tools 目录）→ `npx cap sync android` → 剔除无需内嵌的大文件 →
`gradlew assembleRelease` → 产物自动复制为：

```
im-client/app/bin/im-client.apk
```

签名：`im-client/app/android/keystore.properties` + 对应 keystore 文件。
**APK 覆盖安装要求新旧包签名一致**，换签名后用户必须先卸载再安装。

### 3. 后台上传与启用

1. 登录管理后台 → [客户端更新] → 平台筛选选 **APP（Android APK）**；
2. 点 **[上传新版本]**，填写：
   - 平台：`APP（Android APK）`
   - 版本号（version_name）：与 build.gradle 的 `versionName` 一致，如 `1.1`
   - versionCode：**必填正整数**，与 build.gradle 的 `versionCode` 完全一致，如 `2`
   - 安装包文件：选择 `bin\im-client.apk`（必须 `.apk` 扩展名）
   - 更新说明：客户端更新弹窗展示的文字（≤2000 字）
   - 强制更新：按需勾选
3. 上传成功后在列表中点该版本 **[启用]**。

### 4. 客户端生效

旧版 APP 启动/手动检查时上报当前 versionCode，服务端比对生效版本更高即提示更新，
下载后按 SHA256 校验、拉起系统安装页（Android 无法静默安装）。
APK 落盘位置（服务端静态托管，自动生成下载地址）：`<web_dir>/static/download/android/imapp-<版本>-<code>.apk`

## 三、PC 端（Windows）发布流程

### 1. 修改版本号

文件：`im-client/pc/package.json` 第 3 行

```json
"version": "1.1.0",
```

必须是语义化格式 `x.y.z`，且**严格大于**上一版（electron-updater 与后台登记均按 semver 比较）。
Electron 运行时 `app.getVersion()` 读取的就是该值（打包时固化进 Setup.exe 元数据）。

### 2. 生成 Setup 安装包

前置：先确认 `build.bat` 能正常产出可运行的 `im-client\bin\im-client.exe`
（bundled 目录的内嵌运行时 zip 齐全：node / uv / gcc / rclone / winfsp）。

发布脚本：`im-client/pc/publish-update.bat`（双击运行）

流程：
1. `node obfuscate.js` —— JS 混淆加密；
2. `npx electron-builder --win --x64` —— 按 package.json 的 `build.win.target: nsis` 打 NSIS 安装包；
3. 产物在 `im-client\pc\dist\`：

```
im-client-setup-1.1.0.exe   ← 上传后台用的安装包（文件名自动取 package.json version）
latest.yml                  ← 本地参考用，不需要上传（服务端启用时自动重新生成）
```

> build.bat 与 publish-update.bat 的区别：
> build.bat 产出绿色解压版 bin\im-client.exe（开发调试用）；
> publish-update.bat 产出 NSIS Setup 安装包（发布自动更新用）。

### 3. 后台上传与启用

1. 后台 [客户端更新] → 平台筛选选 **PC（Windows Setup）**；
2. 点 [上传新版本]：
   - 平台：`PC（Windows Setup）`
   - 版本号：`1.1.0`（与 package.json 一致，必须 semver 格式）
   - versionCode：留空（win 平台不使用）
   - 安装包：选择 `dist\im-client-setup-1.1.0.exe`（必须 `.exe`）
   - 更新说明 / 强制更新：按需
3. 点 **[启用]** → 服务端自动重写 `<web_dir>/static/download/win/latest.yml`
   （version/files/path/sha512/size，electron-updater generic feed 兼容格式）。

### 4. 客户端生效

PC 端 updater.js 的 generic feed 指向 `<服务器地址>/static/download/win/`：
- 启动静默检查 + 托盘菜单"检查更新"手动触发；
- 发现新版 → 自绘更新窗展示版本/说明 → 点"立即更新"后台下载（进度条）→
  下载完成"重启安装"全自动覆盖；
- 强制更新（force 经 `/api/app/version?platform=win` 附带下发）：更新窗不可关闭不可跳过；
- 开发/未打包形态（`electron .`、--dir 产物）自动跳过更新逻辑。

## 四、config.yaml 相关配置（可选）

```yaml
# 安装包上传大小上限（字节），缺省 512MB
app_pkg_max_size: 536870912
```

- 安装包落盘目录由 `web_dir` 派生：`<web_dir>/static/download/<platform>/`，静态服务天然托管，无需另配下载地址；
- 修改 config.yaml 后须同步补齐到 `config - linux.yaml`。

## 五、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 上传成功但客户端收不到更新 | 未点 [启用]；或版本号未严格大于当前生效版本 |
| APP 反复提示更新 / 不提示 | build.gradle 的 versionCode 与后台填的值不一致 |
| APK 安装失败（INSTALL_FAILED_VERSION_DOWNGRADE / 签名不符） | versionCode 回退了；或新旧包签名不一致（需卸载重装） |
| PC 检查更新提示"已是最新" | package.json version 没改，或后台 version_name ≤ 客户端当前版本 |
| 想回滚 | 后台 [启用] 旧版本即可（latest.yml 自动重写）；但已强制升级到新版且 force 标记的 PC 用户不会自动降级 |
| 删除生效版本 | 支持（win 删除后自动重写 latest.yml）；同平台无生效版本时客户端检查返回"无更新" |

## 六、发布检查清单

- [ ] 版本号已修改且大于线上生效版本（APP：versionCode+1；PC：semver 递增）
- [ ] 本地安装验证通过（新包能正常启动、登录、核心功能可用）
- [ ] 更新说明文字已准备好（客户端弹窗直接展示给用户）
- [ ] 后台上传 → 核对列表中的版本号/versionCode/大小 → [启用]
- [ ] 用旧版客户端实测收到更新提示并完成升级（强制更新需确认可继续使用）

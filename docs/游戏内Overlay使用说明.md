# 游戏内 Overlay 使用说明

> 面向用户的功能说明与排障指引。技术实现见《游戏内Overlay二期注入式设计.md》。

## 功能简介

从客户端启动游戏后，可以在游戏画面内直接使用好友面板：查看在线好友、私聊、镜像显示联机房间（成员/准备态），并可执行准备/退房操作——无需切出游戏。

## 开启方式

1. 打开 **设置 → 游戏**；
2. 开启 **游戏内面板（Shift+Tab）**——游戏运行期间按 `Shift+Tab` 呼出/收起面板，`Esc` 也可收起；
3. （可选）开启 **游戏内通知**——收到私聊/邀请时游戏右下角弹出小窗，点击直达；
4. （可选，实验）开启 **游戏帧内渲染（实验）**——见下文两种面板形态。

## 两种面板形态

| 形态 | 说明 | 生效条件 |
|---|---|---|
| 游戏帧内渲染（注入式，二期） | 面板直接画进游戏渲染帧（Steam 同款体验），游戏中可直接打字聊天 | 设置开关开启 **且** 游戏在兼容名单内（见下）；从客户端启动游戏 |
| 悬浮窗面板（一期） | 透明悬浮窗覆盖在游戏画面上方 | 其余情况；兼容名单外的游戏自动使用此形态 |

- 兼容名单文件：客户端目录 `overlay-native/native-games.json`。`mode` 为 `list` 时仅名单内游戏启用帧内渲染；改为 `all` 则全部游戏尝试帧内渲染（未知游戏兼容风险自担）。
- 帧内渲染需要以 **窗口化 / 无边框全屏** 模式运行游戏；**独占全屏** 下游戏帧内面板与悬浮窗均不可见（系统机制限制），请切换显示模式。

## 使用要点

- 面板打开期间，键盘鼠标输入归面板使用，游戏收不到输入；收起面板（Shift+Tab / Esc）后立即归还。
- 私聊：好友页点击好友进入会话，输入框回车或点「发送」；消息不落库，仅本次游戏会话内可见。
- 房间镜像：在游戏大厅创建/加入房间后，面板「房间」页签显示房间与成员准备态，可直接「准备」或「退房」。
- 通知小窗：游戏内收到的消息/邀请在右下角堆叠显示，点击可直达聊天或房间。

## 故障排查

| 现象 | 处理 |
|---|---|
| 游戏内按 Shift+Tab 无反应 | 确认游戏是从客户端启动的且处于「运行中」；独占全屏请切无边框/窗口化 |
| 启动器界面里按 Shift+Tab 无反应（游戏还没进） | 正常现象：帧内面板只对真正创建 3D 画面的游戏进程生效，启动器阶段走悬浮窗形态（悬浮窗可用时按 Shift+Tab 呼出）；进入游戏画面后自动切换为帧内面板 |
| 走的是悬浮窗形态（没有注入） | ①「游戏帧内渲染（实验）」是**独立开关**默认关闭，到 设置→游戏 单独开启；②开启后需**重启客户端**（使新配置生效）再**从客户端启动游戏**（注入只发生在启动瞬间）；③确认游戏 exe 在兼容名单内；④客户端日志（`%APPDATA%\im-client-pc\gn-tunnel.log`）搜 `[overlay]` 可见判定原因 |
| 启动器型游戏（先开启动器再点进入游戏）注入没跟上 | 启动器拉起真游戏需经「子进程跟随注入」，日志搜 `follow:` 可见跟随结果；若 `follow list empty, skip` 说明名单未含游戏 exe，请补进兼容名单 |
| 面板能呼出但画面错乱/黑块 | 关闭「游戏帧内渲染（实验）」，使用悬浮窗形态，并向平台反馈游戏名称 |
| 帧内渲染未生效（走的悬浮窗） | 确认游戏 exe 在兼容名单内（`overlay-native/native-games.json`）；或临时把 `mode` 改为 `all` 验证 |
| 注入后游戏启动异常 | 关闭「游戏帧内渲染（实验）」重新启动游戏；帧内渲染失败时客户端会自动回退悬浮窗，正常情况不影响游戏本身 |
| 杀毒软件提示 injector.exe / 注入行为 | 属注入式面板的正常工作机制（向游戏进程写入渲染模块）。若被拦截请将客户端安装目录 `resources\overlay-native\bin\` 加入杀软白名单；正式版客户端这些文件随包签名 |
| 游戏内无法输入中文 | 帧内渲染的输入法支持依赖游戏窗口焦点，部分游戏需切换到悬浮窗形态私聊 |

## 文件位置（打包后）

- 注入组件：安装目录 `resources\overlay-native\bin\`（injector / injector_x64 / overlay_hook_x86 / overlay_hook_x64，随客户端安装包分发，无需放入任何游戏目录）
- 兼容名单：用户副本 `%APPDATA%\<客户端>\overlay-native-games.json`（优先）；分发模板在 `resources\overlay-native\native-games.json`
- 运行日志：`%TEMP%\im-overlay-hook.log`（注入侧）；客户端日志有 `[overlay]` 前缀条目

## 安全与边界

- 注入仅发生在「从客户端启动游戏」且开关/名单允许时；注入失败自动回退，不会导致游戏无法启动。
- 客户端退出或游戏内面板断连后，DLL 自动摘除全部钩子并休眠（不卸载代码页，避免影响游戏）。
- 面板数据（好友/房间/消息）全部由客户端主进程推送，DLL 不持有业务逻辑、不联网。

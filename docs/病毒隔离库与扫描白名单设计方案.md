# 病毒隔离库与扫描白名单设计方案

> 版本：v1.0 | 日期：2026-11-10 | 作者：系统设计

---

## 一、背景与问题

### 1.1 现状

商户上传游戏客户端文件后，服务端通过 ClamAV 病毒扫描（异步模式）对版本落盘文件逐文件送扫：

- **扫描挂点**：`gameVersionCreateCore` 成功登记后异步执行（仅商户名下游戏 + `clamav.enabled=true`）
- **检出处置**：**直接将游戏 `audit_status=3`（已驳回）**，`audit_remark` 携带病毒签名与文件名
- **玩家侧过滤墙**：`audit_status IN (0, 2)`，隔离态与驳回态同等级不可见
- **文件保留**：病毒文件本体保留供取证，但商户必须重新上传整个客户端才能重新提交

涉及核心代码：

| 文件 | 职责 |
|---|---|
| `server/clamav.go` | 扫描核心 `clamScanDir` / `clamScanGameVersionAsync` |
| `server/clamavrescan.go` | 存量版本回溯扫描 |
| `server/gameadmin.go` | 版本上架同步模式挂点 |
| `server/merchantadmin.go` | 人工审核接口 |
| `config/config.go` + `config.yaml` | ClamAV 配置 |

### 1.2 痛点

| 序号 | 问题 | 影响 |
|---|---|---|
| 1 | **一刀切驳回**：ClamAV 检出即驳回，无人工介入判定是误报还是真病毒 | 体验差，误报导致正常商户被阻塞 |
| 2 | **重复上传**：检出后商户必须重新上传整个客户端文件（可能数 GB） | 浪费时间和带宽，大文件上传耗时极长 |
| 3 | **白名单缺失**：已知安全的文件（如签名的启动器、官方 DLL）无法跳过扫描 | 不必要的扫描开销 + 误报风险 |
| 4 | **存量扫描同样问题**：`clamavrescan` 对存量版本回溯扫描也直接驳回 | 线上已运营游戏可能因误报突然下架 |
| 5 | **无可追溯**：检出记录只写了 `audit_remark`，没有独立的隔离记录供管理员后续查阅和统计 | 处置无审计痕迹 |

### 1.3 目标

- ✅ **零数据丢失**：病毒检出后文件保留在磁盘，通过审核后直接可用，商户无需重传
- ✅ **人工可介入**：新增隔离状态，管理员可查看检出详情后判定通过/驳回
- ✅ **白名单机制**：支持 Glob 风格文件匹配，已知安全文件跳过扫描
- ✅ **向后兼容**：配置开关控制新旧行为，存量部署不受影响
- ✅ **安全第一**：隔离态自动过滤玩家可见，与驳回态同等级安全
- ✅ **可追溯审计**：所有检出和处置操作独立落表，支持历史查询和统计

## 二、核心设计

### 2.1 审核状态扩展

在现有 `GameAuditStatus` 四态基础上，新增隔离状态：

```go
// model.go —— 商户游戏审核状态常量扩展
const (
    GameAuditOfficial   = 0 // 官方免审（存量/管理员创建）
    GameAuditPending    = 1 // 待审核（商户新增/编辑对外字段后）
    GameAuditApproved   = 2 // 已通过（玩家侧可见的唯一商户态）
    GameAuditRejected   = 3 // 已驳回（附理由，商户改后可重新提交）
    GameAuditQuarantined = 4 // 已隔离（病毒扫描检出，等待管理员人工确认）
)
```

**玩家侧过滤墙**保持不变：`audit_status IN (0, 2)` → 隔离态和驳回态一样，自动不可见，完全安全。

**状态流转图**：

```
              商户新增/编辑
    ┌────────────────────────┐
    │                        ▼
 [官方免审 0] ────► [待审核 1] ────► [已通过 2]
    ▲                        │          ▲
    │                        │          │
    │    ClamAV检出          │ 管理员   │ 管理员通过
    │                        ▼ 驳回     │ 隔离态处置
    └──────── [已驳回 3]◄─────┤          │
                             │          │
                             ▼          │
                      [已隔离 4]────────┘
                        │
                        │ 管理员确认病毒
                        ▼
                    [已驳回 3]
```

### 2.2 新增数据库表

#### 表一：隔离库记录 `im_clamav_quarantine`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `uint` | PK, AUTO_INCREMENT | 自增ID |
| `game_id` | `uint` | NOT NULL, INDEX | 关联游戏 ID |
| `version_id` | `uint` | NOT NULL, INDEX | 关联版本 ID |
| `game_name` | `varchar(64)` | DEFAULT '' | 游戏名称（冗余，方便列表展示） |
| `slug` | `varchar(64)` | DEFAULT '' | 游戏标识 |
| `version` | `varchar(32)` | DEFAULT '' | 版本号 |
| `owner` | `varchar(32)` | NOT NULL, INDEX | 所属商户账号 |
| `file_path` | `varchar(512)` | NOT NULL | 检出文件相对路径 |
| `file_size` | `bigint` | DEFAULT 0 | 检出文件大小（字节） |
| `file_sha256` | `varchar(64)` | DEFAULT '' | 检出文件 SHA256 哈希（可用于误报验证/白名单） |
| `virus_sig` | `varchar(255)` | NOT NULL | 病毒签名（ClamAV 返回，如 `Eicar-Test-Signature`） |
| `quarantined_at` | `datetime` | | 隔离时间（进入隔离库的时间） |
| `status` | `tinyint` | DEFAULT 0, INDEX | 处置状态：0=待审核 / 1=已通过 / 2=已驳回 |
| `admin_note` | `varchar(500)` | DEFAULT '' | 管理员处置备注 |
| `decided_by` | `varchar(32)` | DEFAULT '' | 处置管理员账号 |
| `decided_at` | `datetime` | | 处置时间 |

**复合索引**：`(game_id, status)` — 方便按游戏查隔离状态；`(owner, status)` — 方便按商户查

**建表方式**：GORM `AutoMigrate` 自动建表，与现有 `im_*` 系列表一致

#### 表二：扫描白名单 `im_clamav_whitelist`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `uint` | PK, AUTO_INCREMENT | 自增ID |
| `scope` | `tinyint` | DEFAULT 0, INDEX | 作用范围：0=全局 / 1=指定游戏 |
| `target_id` | `uint` | DEFAULT 0, INDEX | scope=1 时为 game_id；scope=0 时填 0 |
| `file_pattern` | `varchar(255)` | NOT NULL | Glob 风格匹配模式（见 2.3 节） |
| `reason` | `varchar(255)` | DEFAULT '' | 添加原因（如"官方签名的启动器"） |
| `enabled` | `tinyint` | DEFAULT 1 | 是否启用：1=启用 / 0=禁用 |
| `created_by` | `varchar(32)` | DEFAULT '' | 添加管理员账号 |
| `created_at` | `datetime` | | 添加时间 |

**Glob 匹配模式示例**：

| 模式 | 含义 | 匹配例子 |
|---|---|---|
| `*.dll` | 所有 DLL 文件 | `launcher.dll`、`bin/x86/d3d9.dll` |
| `bin/launcher.exe` | 特定路径文件 | 精确匹配 |
| `patch_*` | 前缀通配 | `patch_v1.dat`、`patch_001.bin` |
| `*key*.dat` | 包含通配 | `license_key.dat`、`keyfile.dat` |
| `*.dat` | 所有 DAT 文件 | 任意位置 `.dat` 后缀 |

**匹配算法**：使用 Go 标准库 `filepath.Match`，对文件的相对路径（从版本根目录起）进行匹配。

### 2.3 病毒扫描流程改造

#### 改造点 1：`clamScanGameVersionAsync`（新增版本异步扫描）

**原逻辑**：
```go
检出病毒 → UPDATE game SET audit_status=3, audit_remark=...
```

**新逻辑**（当 `quarantine_on_detect=true` 时）：
```
检出病毒 →
  1. 写入 im_clamav_quarantine（每个检出文件一行，file_path/file_size/file_sha256/virus_sig 等）
  2. UPDATE game SET audit_status=4, audit_remark="病毒扫描检出 N 项，已进入隔离库待管理员审核"
  3. WS 推隔离通知（type="game_quarantined"，新增推送类型）
  4. 文件保留在磁盘不动 ← 关键：不删文件！
```

**当 `quarantine_on_detect=false` 时**：保持旧行为不变（直接驳回）。

#### 改造点 2：`clamavrescan.go`（存量回溯扫描）

同样，检出后改为隔离而非直接驳回。对同游戏同一版本的多条检出记录去重（按 `file_path`）。

#### 改造点 3：白名单检查（在 `clamScanDir` 中挂接）

在扫描每个文件前，先检查白名单：

```go
// 伪代码示意
func clamScanDir(...) {
    for 每个文件:
        relPath := 相对于版本根目录的路径
        if isWhitelisted(relPath, gameID):
            跳过扫描，记 debug 日志，计入 skipped
            continue
        正常扫描流程...
}
```

**白名单匹配逻辑**：

```go
// 内存缓存（与网盘黑名单/链接白名单体系一致，热更落库+内存刷新）
func isWhitelisted(relPath string, gameID uint) bool {
    for _, rule := range clamavWhitelistCache {
        if !rule.Enabled {
            continue
        }
        if rule.Scope == 1 && rule.TargetID != gameID {
            continue
        }
        if matched, _ := filepath.Match(rule.FilePattern, relPath); matched {
            return true
        }
    }
    return false
}
```

#### 改造点 4：`gameVersionCreateCore`（同步模式挂点）

同步模式检出病毒时，返回明确的隔离提示：

```json
{
  "ok": false,
  "msg": "病毒扫描检出 N 项（签名：xxx），已进入隔离库等待管理员审核，请耐心等待"
}
```

### 2.4 管理员处置流程

在管理后台「安全」区域新增**隔离库管理**视图，提供三种处置操作：

#### 操作一：通过审核（放行）

**语义**：管理员确认这些 ClamAV 检出是误报（或已知安全），放行游戏。

```sql
-- 批量更新游戏状态
UPDATE im_game
SET audit_status = 2, audit_remark = '', audit_time = NOW(), audited_by = ?
WHERE id = ? AND audit_status = 4;

-- 批量更新隔离记录为已通过
UPDATE im_clamav_quarantine
SET status = 1, admin_note = ?, decided_by = ?, decided_at = NOW()
WHERE game_id = ? AND status = 0;
```

**后续影响**：
- 游戏立即从隔离态变为已通过，玩家侧可见
- WS 推 `audit_status=2` 给商户（复用 `emitGameAuditChanged`）
- 隔离记录不再阻塞，可清理

#### 操作二：确认病毒（驳回）

**语义**：管理员确认检出是真实病毒，驳回游戏要求商户整改。

```sql
UPDATE im_game
SET audit_status = 3, audit_remark = ?, audit_time = NOW(), audited_by = ?
WHERE id = ? AND audit_status = 4;

UPDATE im_clamav_quarantine
SET status = 2, admin_note = ?, decided_by = ?, decided_at = NOW()
WHERE game_id = ? AND status = 0;
```

**后续影响**：
- 游戏变为已驳回，玩家侧不可见（本来就不可见）
- WS 推 `audit_status=3` 给商户，商户看到驳回理由
- 商户需修改后重新提交，走正常审核流程

#### 操作三：清理已处置记录

- **定时任务**：隔离记录 `status != 0` 且 `decided_at` 超过 `max_quarantine_age_days`（默认 30 天）后自动清理
- **手动触发**：管理员可在隔离库管理页面点击「清理已处置记录」按钮
- **只清理非待审核的**：`status=0`（待审核）的记录永远不会被自动清理

### 2.5 商户端体验优化

商户端收到隔离通知后：

| 变化 | 说明 |
|---|---|
| **WS 推送** | 新增 `type="game_quarantined"` 消息，携带 `game_id`、`audit_remark`、检出文件数 |
| **列表展示** | 「我的游戏」列表中隔离态游戏显示灰色隔离标记 + 提示文案 |
| **无需操作** | 商户看到隔离提示后**无需重新上传**，只需等待管理员审核结果 |
| **状态轮询** | 未接 WS 的商户页靠定时轮询（复用现有 `audit_status` 轮询）兜底 |

**状态文案**：

| audit_status | 商户端展示文案 |
|---|---|
| 0 | 官方游戏（无需审核） |
| 1 | 待审核 |
| 2 | 已通过 |
| 3 | 已驳回（附理由） |
| **4（新）** | **已隔离：病毒扫描检出 N 项，等待管理员确认** |

### 2.6 配置文件扩展

`config.yaml` 中 `clamav` 节新增可选配置：

```yaml
clamav:
  enabled: true
  addr: "127.0.0.1:3310"
  timeout_sec: 600
  sync: false
  quarantine_on_detect: true    # ← 新增：true=检出进隔离库（新行为，推荐）；false=直接驳回（兼容旧行为）
  max_quarantine_age_days: 30   # ← 新增：已处置隔离记录最长保留天数
```

**默认值**：
- `quarantine_on_detect` 默认 `true`（新部署推荐隔离库模式）
- `max_quarantine_age_days` 默认 `30`

**同步要求**：`config.yaml` 修改后，必须同步到 `config - linux.yaml`（项目开发规则要求）。

## 四、后端接口清单

所有接口挂在 `adminGuard` 下，返回统一 `{ok, data}` / `{ok, msg}` 格式。

### 4.1 隔离库接口

| 方法 | 路径 | 说明 | 请求参数 | 响应 |
|---|---|---|---|---|
| GET | `/admin/api/security/quarantine/list` | 隔离库记录列表 | `status`(可选 0/1/2), `owner`(可选), `game_id`(可选), `page`, `size` | `{total, items: [...]}` |
| GET | `/admin/api/security/quarantine/{id}` | 单条隔离记录详情 | — | 完整记录 + 同游戏其他检出记录 |
| POST | `/admin/api/security/quarantine/{id}/approve` | 通过审核（放行） | `admin_note`(可选) | `{ok: true}` |
| POST | `/admin/api/security/quarantine/{id}/reject` | 确认病毒（驳回） | `admin_note`(必填, ≤500字) | `{ok: true}` |
| DELETE | `/admin/api/security/quarantine/cleanup` | 清理已处置记录 | — | `{cleaned: N}` |

**隔离库列表项字段**：

```json
{
  "id": 1,
  "game_id": 100,
  "game_name": "XXX Game",
  "slug": "xxx-game",
  "version": "v1.2.0",
  "owner": "merchant01",
  "hit_count": 3,
  "first_sig": "Trojan.Agent",
  "first_file": "bin/launcher.exe",
  "quarantined_at": "2026-11-10 14:30:22",
  "status": 0
}
```

### 4.2 白名单接口

| 方法 | 路径 | 说明 | 请求参数 |
|---|---|---|---|

## 八、验收标准

| 序号 | 验收项 | 通过条件 |
|---|---|---|
| 1 | 病毒检出不丢文件 | 检出后游戏文件保留在磁盘，管理员通过审核后游戏立即可用 |
| 2 | 隔离态玩家不可见 | `audit_status=4` 的游戏在玩家端所有发现面不出现 |
| 3 | 隔离态商户可见 | 商户端隔离态显示灰色标记和清晰提示文案 |
| 4 | 白名单跳过扫描 | 白名单内的文件不被送扫，不计入扫描耗时 |
| 5 | Glob 匹配正确 | 各种模式（`*.dll`、`path/file.exe`、`prefix_*`）行为符合预期 |
| 6 | 热更生效 | 白名单规则增删改后，下次扫描立即生效（无需重启） |
| 7 | WS 实时推送 | 病毒检出 → 隔离 → 通过/驳回全链路商户端实时收到通知 |
| 8 | 历史回溯安全 | `clamavrescan` 不再直接下架线上游戏，检出进隔离库 |
| 9 | 配置兼容 | 旧 config.yaml 不补新字段时系统正常运行 |
| 10 | 清理自动化 | 已处置记录超过 30 天后自动清理，不影响待审核记录 |

## 九、安全性考虑

| 风险 | 缓解措施 |
|---|---|
| 隔离文件被恶意访问 | 隔离态 `audit_status=4`，玩家侧所有下载/可见接口都过滤 `IN (0,2)` |
| 管理员权限滥用 | 隔离库接口走 `adminGuard`，只有管理员可处置；操作记录含 `decided_by` 可审计 |
| 白名单被恶意添加 | 白名单接口走 `adminGuard`；可通过 `enabled` 字段暂时禁用某条规则 |
| 白名单范围过大 | 新增规则时 scope 默认为 0（全局）；管理员需显式选择全局/指定游戏 |
| 隔离文件被删除 | 隔离库记录与文件路径解耦，若文件已不存在（如被版本删除接口清理），处置时跳过文件验证 |
| 并发隔离 | 同一游戏同一版本多次扫描不会产生重复隔离记录（按 `game_id + file_path` 去重） |

## 十、与现有体系的关系

### 10.1 与网盘黑名单的关系

| 维度 | 网盘黑名单（`im_drive_file`） | 扫描白名单（本次） |
|---|---|---|
| 管控对象 | 网盘上传文件的**文件扩展名** | 游戏版本文件的**内容（ClamAV 扫描）** |
| 作用 | 阻止 `.exe/.bat` 等直接通过网盘分发 | 让已知安全文件跳过病毒扫描 |
| 热更方式 | DB 热更 | DB 热更 |
| 互斥 | 二者独立不冲突——白名单跳过 ClamAV 扫描，但扩展名黑名单仍然生效 |

### 10.2 与链接白名单的关系

二者都是 DB 热更 + 内存缓存模式，白名单匹配逻辑（Glob vs URL 域名）不同，但管理后台视图风格可参考链接白名单的实现。

### 10.3 与版本删除的关系

隔离中的游戏版本若被管理员手动删除，隔离库中的对应记录会失去引用（但保留记录供审计）。处置时若发现版本已不存在，自动清理隔离记录。

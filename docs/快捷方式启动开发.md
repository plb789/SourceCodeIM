## 一、需求概述

在 PC 端游戏库左侧列表右键菜单中增加「创建桌面快捷方式」选项，用户点击后在桌面生成 `.lnk` 快捷方式文件，双击快捷方式即可直接启动对应游戏。参考 Steam 和 WeGame 的实现模式。

### 1.1 核心要求

| # | 要求 | 说明 |
|---|------|------|
| 1 | 快捷方式能启动游戏 | 双击桌面图标 → 游戏启动 |
| 2 | 复用已有功能链 | 云存档、端口转发、SmartSteamEmu、游戏内 Overlay 全部联动 |
| 3 | 零运行库依赖 | 不用 PowerShell、不用 VBScript、不用 Python，单 exe 直接跑 |
| 4 | 支持商店游戏 + 本地游戏 | 两类游戏都能创建快捷方式 |
| 5 | 支持创建 + 删除 | 右键菜单增加「删除桌面快捷方式」入口 |
| 6 | 多实例冲突处理 | 已有 IM 客户端运行时，快捷方式应传递启动信号而非再开一个实例 |

### 1.2 交互设计

```
游戏库左侧列表 → 右键
    ├── 正在启动 / 运行中           （根据状态显示，灰显）
    ├── 启动游戏
    ├── 创建桌面快捷方式           ← 新增
    ├── 删除桌面快捷方式           ← 新增（有快捷方式时才显示）
    ├── 属性
    └── 移出游戏库 / 从库中移除（本地游戏）
```

## 二、方案选型

### 2.1 快捷方式启动目标：方案 B（启动客户端 + 参数）

**Steam 模式**：`steam://rungameid/12345` → 通过 URI 协议拉起 Steam 客户端 → 客户端启动游戏

**WeGame 模式**：`WeGame.exe launch --gameId=xxx` → 快捷方式指向 WeGame 客户端 → 客户端启动游戏

**本项目方案 B**：快捷方式指向 `im-client.exe`，带 `--launch-game <gameId>` 参数。

### 2.2 为什么选方案 B 不选方案 A

| 对比项 | 方案 A：快捷方式直接启动游戏 exe | 方案 B：快捷方式启动 im-client.exe + 参数 |
|--------|--------------------------------|------------------------------------------|
| 云存档同步 | ❌ 绕过客户端，无存档 | ✅ 走完整链路，云存档联动 |
| 端口透传转发 | ❌ 无法开启 | ✅ 完全联动 |
| SmartSteamEmu | ❌ 无 ini 写入、无注入 | ✅ 与应用内启动完全一致 |
| 游戏内 Overlay | ❌ 无法注入 | ✅ 自动注入 Shift+Tab |
| 账号登录态 | ❌ 不检查 | ✅ 自动检查，未登录弹登录窗 |
| 实现复杂度 | 低 | 中（需处理单实例通信） |
| 用户体验 | 差（游戏裸启动） | 好（与 Steam/WeGame 一致） |

### 2.3 创建快捷方式的底层技术选型

| 方案 | 依赖 | 优缺点 |
|------|------|--------|
| PowerShell + WScript.Shell | PowerShell 5 + ExecutionPolicy | ❌ ExecutionPolicy 可能被组策略禁用；❌ 中文路径编码问题 |
| VBScript (.vbs) | Windows Script Host | ⚠️ WSH 也可能被组策略禁用；⚠️ 无进度/错误反馈窗口 |
| **纯 C + IShellLinkW COM** | 仅 Windows Shell | ✅ 零运行库依赖；✅ `/MT` 静态 CRT；✅ 与项目 elevator.c 风格一致 |
| Node.js child_process + cmd | 打包后 Node runtime | ❌ child_process 带 powershell/cmd 依赖；❌ 同 PowerShell 问题 |

**选定：纯 C + IShellLinkW COM 接口**

理由：
1. 项目已有 elevator.c 纯 C Win32 辅助工具的成熟模式（`/MT`、`/SUBSYSTEM:WINDOWS`、manifest 嵌入）
2. IShellLinkW 是 Windows Shell 原生 COM 接口，系统自带，不需要任何运行库
3. 编译成单 exe 随客户端分发，Electron main.js 通过 `child_process.spawnSync` 调用

## 四、C 辅助工具：shortcut-helper.exe

### 4.1 概述

路径：`im-client/pc/shortcut-helper/shortcut-helper.c`  
构建：同目录 `build-shortcut-helper.bat`（VS2022 x64），编完 exe 留在本目录  
打包分发：通过 `electron-builder` 的 `extraResources` 打入 `resources/shortcut-helper/`，  
源码目录（.c / .bat / .rc）在打包时排除，只带编译产物 exe（见第八章）

**技术栈**：纯 C + Win32 + IShellLinkW COM + `/MT` 静态 CRT  
**系统需求**：Windows 7 及以上（IShellLinkW 从 Win95 就有，兼容所有目标机）  
**运行库依赖**：零（kernel32.lib, user32.lib, ole32.lib, shell32.lib）

### 4.2 命令行接口

```
shortcut-helper.exe <command> [options]

命令：
  create     创建快捷方式
  delete     删除快捷方式
  exists     检查快捷方式是否存在（exit code: 0=存在, 1=不存在, 2=错误）

create 选项：
  --name <str>         快捷方式显示名称（不含 .lnk 后缀），必填
  --target <path>      目标程序完整路径，必填
  --args <str>         传递给目标程序的命令行参数，可空
  --workdir <path>     工作目录（StartIn），必填
  --icon <spec>        图标来源，格式: "exePath,iconIndex" 或纯 exePath，可空
  --desktop            创建到桌面
  --startmenu          创建到开始菜单（待后续迭代）
  --overwrite          已存在时覆盖，默认拒绝并返回错误

delete 选项：
  --name <str>         快捷方式名称
  --desktop            从桌面删除
  --startmenu          从开始菜单删除

输出：JSON 到 stdout（成功/错误统一 JSON，方便 Node.js 解析）
  成功：{"ok":true,"path":"C:\\Users\\xxx\\Desktop\\游戏名.lnk"}
  失败：{"ok":false,"error":"错误描述","code":123}
```

### 4.3 核心实现（IShellLinkW COM）

```c
// shortcut-helper.c 核心伪代码

#include <windows.h>
#include <shlobj.h>    // IShellLinkW, IPersistFile, SHGetFolderPathW
#include <stdio.h>

#pragma comment(lib, "ole32.lib")
#pragma comment(lib, "shell32.lib")
#pragma comment(lib, "user32.lib")

// COM 初始化 + 创建 IShellLinkW 接口
HRESULT CoCreateShellLink(IShellLinkW **ppLink) {
    CoInitializeEx(NULL, COINIT_APARTMENTTHREADED);
    return CoCreateInstance(
        &CLSID_ShellLink, NULL, CLSCTX_INPROC_SERVER,
        &IID_IShellLinkW, (void **)ppLink
    );
}

// 创建快捷方式核心
int cmd_create(const Options *opt) {
    IShellLinkW *pLink = NULL;
    IPersistFile *pFile = NULL;
    HRESULT hr;

    hr = CoCreateShellLink(&pLink);
    if (FAILED(hr)) return fail(L"CoCreateInstance 失败");

    // 设置目标路径（快捷方式 TargetPath）
    pLink->lpVtbl->SetPath(pLink, opt->target);

    // 设置命令行参数（快捷方式 Arguments）
    if (opt->args && *opt->args)
        pLink->lpVtbl->SetArguments(pLink, opt->args);

    // 设置工作目录（快捷方式 StartIn）
    if (opt->workdir && *opt->workdir)
        pLink->lpVtbl->SetWorkingDirectory(pLink, opt->workdir);

    // 设置图标（快捷方式 IconLocation）
    if (opt->icon && *opt->icon)
        pLink->lpVtbl->SetIconLocation(pLink, opt->iconPath, opt->iconIndex);

    // 解析桌面路径
    WCHAR desktop[MAX_PATH];
    if (opt->desktop)
        SHGetFolderPathW(NULL, CSIDL_DESKTOPDIRECTORY, NULL, 0, desktop);
    else if (opt->startmenu)
        SHGetFolderPathW(NULL, CSIDL_STARTMENU, NULL, 0, desktop);

    // 拼接快捷方式完整路径
    WCHAR lnkPath[MAX_PATH];
    wsprintfW(lnkPath, L"%s\\%s.lnk", desktop, opt->name);

    // 检查是否已存在
    if (!(opt->flags & FLAG_OVERWRITE) && GetFileAttributesW(lnkPath) != INVALID_FILE_ATTRIBUTES) {
        CoUninitialize();
        return failA("快捷方式已存在（--overwrite 可覆盖）");
    }

    // QueryInterface 获取 IPersistFile → Save 到 .lnk
    hr = pLink->lpVtbl->QueryInterface(pLink, &IID_IPersistFile, (void **)&pFile);
    if (SUCCEEDED(hr)) {
        hr = pFile->lpVtbl->Save(pFile, lnkPath, TRUE); // TRUE=绝对路径
        pFile->lpVtbl->Release(pFile);
    }

    pLink->lpVtbl->Release(pLink);
    CoUninitialize();

    if (FAILED(hr)) return fail(L"保存 .lnk 文件失败");
    return ok(lnkPath);
}
```

### 4.4 关键细节

#### 4.4.1 中文路径

IShellLinkW 全程用 WCHAR（UTF-16），Windows Shell API 原生支持中文路径，不存在 PowerShell/VBScript 的编码问题。

#### 4.4.2 名称非法字符过滤

Windows 快捷方式文件名不能包含 `\/:*?"<>|`，需要过滤为 `_`：

```c
static void sanitizeName(WCHAR *out, const WCHAR *in) {
    static const WCHAR bad[] = { L'\\', L'/', L':', L'*', L'?', L'"', L'<', L'>', L'|', 0 };
    while (*in) {
        if (wcschr(bad, *in)) *out++ = L'_';
        else *out++ = *in;
        in++;
    }
    *out = 0;
}
```

#### 4.4.3 图标来源（核心：让 Shell 从游戏 exe 资源段读取，不自己解析）

**shortcut-helper.c 只传一个路径，一行 API 搞定**：

```c
// Windows Shell 自己从 exe 的资源段读图标，一行 SetIconLocation 完事
// 不需要 ExtractIcon / 不需要手动解析 .ico / 不需要 PNG 落盘
if (opt->iconPath && *opt->iconPath) {
    pLink->lpVtbl->SetIconLocation(pLink, opt->iconPath, opt->iconIndex);  // opt->iconIndex 默认 0
}
```

**和项目已有两处图标读取同源**：

| 用途 | 代码位置 | 实现方式 |
|------|---------|---------|
| 本地游戏侧栏图标（网页内 PNG 显示） | `main.js :: local-game:get-icon` | `app.getFileIcon(exe)` → Electron 内部调 Shell → 转 PNG dataURL 给渲染层 |
| **本次：桌面快捷方式图标** | shortcut-helper.c | `IShellLinkW.SetIconLocation(exePath, 0)` → **直接调 Shell 读图标 → 嵌入 .lnk** |

差异：前者要转 PNG 给网页 img 标签；后者只要告诉 Shell 图标位置，Shell 自己处理。后者更简单。

##### main.js 如何给 shortcut-helper 传递 icon 路径

```
场景 A：商店游戏（已安装，state.lib[gid].state === 3 或 4）
──────────────────────────────────────────────────────────
  var reg = gameLaunchRegLoad();                // 项目已有启动注册表
  var r = gameResolveLaunchExe(reg, gameId, {}); // 项目已有 EXE 解析逻辑
  // gameResolveLaunchExe 内部优先级：
  //   1. 用户自定义（gameLaunchReg.exe）
  //   2. 管理端下发（game.launch_exe / game.launch_name）
  //   3. 自动探测 install_dir 下的 exe
  var iconPath = r ? r.exe : '';                // ← 传给 --icon

场景 B：本地游戏
──────────────
  var iconPath = state.localLib[lid].exe;        // 用户选的 exe，直接可用
  // 这条路径在保存属性时已 fs.existsSync 校验过

场景 C：SmartSteamEmu 游戏
──────────────────────────
  gameResolveLaunchExe 会解析到实际游戏 exe（不是 Steam.exe loader）
  快捷方式图标 = 真实游戏图标（Steam.exe 只是启动壳）
```

##### 图标缺失兜底链

```
游戏 exe 路径不存在（安装目录被删）
  → iconPath 传空串
  → Shell 自动回退到 TargetPath（im-client.exe 自身图标）
  → 快捷方式仍能双击启动（指向 im-client.exe 的 --launch-game）
  → 客户端启动后会提示"游戏未安装"（与 Steam 卸载后残留快捷方式行为一致）

exe 没有嵌入图标（极少见）
  → Shell 用系统默认 exe 图标
  → 不影响功能

游戏 exe 是 Steam.exe / 启动器 / 包装器（非真实游戏）
  → gameResolveLaunchExe 有 excludeRoot 排除逻辑（game:launch 已用）
  → 解析到真实游戏 exe 路径再传给 --icon
```

##### 关键代码（main.js :: game:create-shortcut IPC 内）

```javascript
ipcMain.handle('game:create-shortcut', async function (event, data) {
    var gameId = String((data && data.gameId) || '');
    var isLocal = !!(data && data.isLocal);
    var iconPath = '';

    if (isLocal) {
        // 本地游戏：渲染层已传 exePath（用户选的）

    } else {

        iconPath = r ? r.exe : '';
    }

    // 兜底：exe 不存在时用 im-client.exe 图标
    if (!iconPath || !fs.existsSync(iconPath)) {
        iconPath = app.getPath('exe');
    }

    var helperArgs = [
        'create', '--name', name,
        '--target', clientExe, '--args', args, '--workdir', workDir,
        '--icon', iconPath + ',0',   // ← 这就是游戏自身 exe 的图标！
        '--desktop', '--overwrite'
    ];
    // ... spawnSync 调 helper
});
```

#### 4.4.4 编译参数

```bat
cl /nologo /utf-8 /MT /O2 /W3 shortcut-helper.c shortcut-helper.rc ^
    /Fe:shortcut-helper.exe /link /SUBSYSTEM:CONSOLE ole32.lib shell32.lib user32.lib
```

注意用 `/SUBSYSTEM:CONSOLE`（不是 WINDOWS），因为 main.js 用 spawnSync 调它，需要捕获 stdout JSON。

#### 4.4.5 manifest

不需要 `requireAdministrator` manifest（创建桌面快捷方式不需要管理员权限），用默认 `asInvoker` 即可。

## 五、main.js 改动

### 5.1 新增 IPC：创建快捷方式

```javascript
// ===== 阶段 XXX：桌面快捷方式创建 =====
// shortcut-helper.exe 路径：
//   打包态 → resources/shortcut-helper/shortcut-helper.exe（extraResources 打入）
//   开发态 → pc/shortcut-helper/shortcut-helper.exe（源码目录）
// 与项目其他 extraResources 辅助工具（dlbt-host / game-visible / Driver）同口径
function shortcutHelperPath() {
    var dir = app.isPackaged
        ? path.join(process.resourcesPath, 'shortcut-helper')
        : path.join(__dirname, 'shortcut-helper');
    return path.join(dir, 'shortcut-helper.exe');
}

ipcMain.handle('game:create-shortcut', async function (event, data) {
    try {
        var helper = shortcutHelperPath();
        if (!fs.existsSync(helper)) return { ok: false, error: '快捷方式辅助工具缺失' };

        var name = String((data && data.name) || 'Game');
        var gameId = String((data && data.gameId) || '');
        var isLocal = !!(data && data.isLocal);

        // 目标程序：im-client.exe（方案 B：启动客户端带参数）
        var clientExe = app.getPath('exe');
        var workDir = path.dirname(clientExe);
        var args = '--launch-game ' + gameId;

        // ===== 图标路径：游戏自身 exe（让 Shell 从资源段读取）=====
        var iconPath = '';
        if (isLocal) {
            // 本地游戏：渲染层直接传 exePath（用户选的，已校验过 exists）
            iconPath = String((data && data.exePath) || '');
        } else {
            // 商店游戏：main.js 自己解析（与 game:launch 同逻辑同优先级）
            //   1. 用户自定义（gameLaunchReg.exe）
            //   2. 管理端下发（game.launch_exe / game.launch_name）
            //   3. 自动探测 install_dir 下的 exe
            var reg = gameLaunchRegLoad();
            var r = gameResolveLaunchExe(reg, gameId, {});
            iconPath = r ? r.exe : '';
        }
        // 兜底：exe 路径无效时用 im-client.exe 自身图标
        if (!iconPath || !fs.existsSync(iconPath)) {
            iconPath = clientExe;
        }

        // 构建命令行参数数组（spawnSync 数组传参自动处理路径含空格）
        var helperArgs = [
            'create',
            '--name', name,
            '--target', clientExe,
            '--args', args,
            '--workdir', workDir,
            '--icon', iconPath + ',0',      // ← 游戏自身 exe 图标（Shell 读资源段）
            '--desktop',
            '--overwrite'
        ];

        var result = child_process.spawnSync(helper, helperArgs, {
            encoding: 'utf-8',
            timeout: 10000,
            windowsHide: true
        });

        // 解析 stdout JSON
        if (result.status !== 0) {
            return { ok: false, error: (result.stderr || '未知错误').trim() };
        }
        var out = JSON.parse((result.stdout || '').trim());
        return out; // {ok:true, path:"..."} 或 {ok:false, error:"..."}
    } catch (e) {
        return { ok: false, error: (e && e.message) || '创建快捷方式异常' };
    }
});
```

### 5.2 新增 IPC：删除快捷方式 + 检查存在性

```javascript
// 删除桌面快捷方式
ipcMain.handle('game:delete-shortcut', async function (event, data) {
    var helper = shortcutHelperPath();
    if (!fs.existsSync(helper)) return { ok: false, error: '快捷方式辅助工具缺失' };

    var name = String((data && data.name) || '');
    var result = child_process.spawnSync(helper, [
        'delete', '--name', name, '--desktop'
    ], { encoding: 'utf-8', timeout: 5000, windowsHide: true });

    if (result.status !== 0) return { ok: false, error: (result.stderr || '').trim() };
    return JSON.parse((result.stdout || '').trim());
});

// 检查快捷方式是否存在（右键菜单决定显示"创建"还是"删除"）
ipcMain.handle('game:shortcut-exists', async function (event, data) {
    var helper = shortcutHelperPath();
    if (!fs.existsSync(helper)) return { ok: true, exists: false };

    var name = String((data && data.name) || '');
    var result = child_process.spawnSync(helper, [
        'exists', '--name', name, '--desktop'
    ], { encoding: 'utf-8', timeout: 5000, windowsHide: true });

    if (result.status === 0) return { ok: true, exists: true };
    if (result.status === 1) return { ok: true, exists: false };
    return { ok: false, error: (result.stderr || '').trim() };
});
```

### 5.3 启动参数解析（whenReady 处）

### 5.4 单实例通信（已运行实例收到启动信号 → 静默启动，不打扰客户端窗口）

#### 核心设计

**完全可行，且推荐这样做。** 原因如下：

```
渲染层 launchGame() 做了两件事：
  ① 云存档同步（pull）         → DESKTOP.gameSaveSync → 主进程 game:save-sync
  ② 构建 payload 传给主进程     → DESKTOP.gameLaunch   → 主进程 game:launch

主进程 game:launch 内部做了所有真正的事：
  ✓ 解析 exe（gameResolveLaunchExe）
  ✓ 防火墙放行（fwEnsureForLaunch）
  ✓ 端口转发（gameForward.start）
  ✓ SmartSteamEmu（spawnSteamEmuGame）
  ✓ spawn 游戏进程
  ✓ Overlay 热键（gameOverlay.onGameStart）
  ✓ 进程监控（exit / error / waitGameWindowVisible）
```

**所有启动链路在主进程内闭环。** 渲染层只是传参数和展示 UI。因此 second-instance 触发时，主进程完全可以自己闭环启动游戏，不涉及渲染层、不改变 mainWindow 状态。

#### 游戏库状态自动更新（天然可用，无需额外代码）

用户关心的关键问题：**静默启动后游戏库页面（即使最小化/托盘）的"启动中 → 运行中 → 已退出"状态能否自动更新？**

**答案：能。且现有全窗口广播机制天然覆盖这个场景，不需要写任何额外代码。**

```
主进程静默启动链路                 渲染层（游戏库页面）
─────────────────────            ──────────────────
mainSilentLaunchGame()
  │
  ├─ spawn 成功
  │    └─ gameLaunchBroadcast()   → BrowserWindow.getAllWindows().webContents.send('game-launching', {gameId})
  │                               → 窗口最小化？IPC 消息不丢，排队等恢复
  │                               → 渲染层 onGameLaunching 收到
  │                               → state.launching[gid] = Date.now()
  │                               → scheduleRefresh() UI 切"正在启动"
  │
  ├─ 游戏窗口可见
  │    └─ gameStartBroadcast()    → send('game-start', {gameId})
  │                               → 渲染层 delete launching, state.running[gid] = ...
  │                               → scheduleRefresh() UI 切"运行中"
  │                               → api POST game/play/{gid} start（服务端 presence）
  │
  └─ 游戏退出
       └─ gameExitBroadcast()     → send('game-exit', {gameId})
                                  → 渲染层 delete running, delete sessions
                                  → api POST game/play/{gid} end（结算时长）
                                  → gameSaveSync push（退出上传存档）
```

**关键结论**：

| 广播 | 主进程代码 | 窗口状态影响 |
|------|-----------|------------|
| game-launching（正在启动） | `gameLaunchBroadcast()` — 全窗口 send | 不管窗口可见/最小化/托盘，消息**一定送达** |
| game-start（运行中） | `gameStartBroadcast()` — 全窗口 send | 同上 |
| game-exit（已退出） | `gameExitBroadcast()` — 全窗口 send | 同上 |
| game-launch-error（失败） | 内联 `w.webContents.send('game-launch-error', ...)` | 同上 |

Electron 窗口最小化/隐藏到托盘时：
- webContents **进入后台节流**（requestAnimationFrame 停止、setTimeout 间隔拉长）
- 但 **IPC 消息绝不丢弃**，排队在渲染进程事件循环里
- 窗口恢复可见后，事件循环立即处理积压的广播消息 → state 被正确更新 → 首帧渲染即显示正确状态

**兜底机制**：即使极端情况下广播丢失（比如窗口被 destroy 又重建），渲染层页面加载时会调 `DESKTOP.gameRunningList()` 主动查询主进程 `runningGames` Map —— 状态一定能恢复。

#### mainSilentLaunchGame：主进程闭环静默启动

```javascript
// ===== 静默启动游戏（second-instance 触发，不经过渲染层）=====
// 与渲染层 launchGame() 等价，但 mainWindow 状态不变
// 启动链路：云存档同步 → 构建 payload → 调 gameLaunch 内部函数
async function mainSilentLaunchGame(gid, isLocal) {
    try {
        // 1. 登录态检查（从 userData 读取 localStorage 等价数据）
        var auth = mainReadAuth(); // 主进程读 userData 里保存的登录凭证
        if (!auth) {
            // 未登录无法启动，只记录日志，不弹窗打扰
            mainLog('[silent-launch] 未登录，跳过启动 gameId=' + gid);
            return;
        }

        if (isLocal) {
            // —— 本地游戏静默启动（无云存档/端口转发/SSE/服务端配置 ——）
            var lo = mainReadLocalGame(gid); // userData/local-games.json
            if (!lo || !lo.exe || !fs.existsSync(lo.exe)) return;
            // 端口转发（本地游戏自己配的规则，从 localStorage 读）
            var pfRules = lo.portForwards || [];
            var pfTag = 'local:' + gid;
            if (pfRules.length) {
                var pfRet = await gameForward.start(pfTag, pfRules, null);
                if (!pfRet.ok) { mainLog('[silent-launch] 端口转发失败'); return; }
            }
            var spawned = spawnGameChild(lo.exe, [], path.dirname(lo.exe), { windowsHide: true });
            var child = spawned.child;
            runningLocalGames.set(gid, { proc: child, startedAt: Date.now() });
            gameOverlay.onGameStart(gid, child.pid);
            child.once('exit', function () {
                runningLocalGames.delete(gid);
                gameOverlay.onGameExit(gid);
                if (pfRules.length) gameForward.stop(pfTag);
            });
            child.once('error', function () {
                runningLocalGames.delete(gid);
                gameOverlay.onGameExit(gid);
                if (pfRules.length) gameForward.stop(pfTag);
            });
            child.unref();
            return;
        }

        // —— 商店游戏静默启动 ——
        var reg = gameLaunchRegLoad();
        var r = gameResolveLaunchExe(reg, gid, {});
        if (!r) return; // needExe：静默模式不弹框，放弃

        // 2. 云存档同步（pull，主进程 gameSave 模块内部函数）
        //    渲染层是 DESKTOP.gameSaveSync → IPC game:save-sync
        //    这里直接调 gameSave.syncPull 内部函数（同进程不需要 IPC）
        var libInfo = mainGetGameLibInfo(gid); // 从 userData/game-lib.json 读 install_path 等
        if (libInfo && libInfo.install_path) {
            try {
                await gameSave.syncPull({
                    gameId: gid,
                    installDir: libInfo.install_path,
                    username: auth.username,
                    gateway: mainGetGateway()
                });
            } catch (e) { mainLog('[silent-launch] 云存档 pull 失败（不阻断）'); }
        }

        // 3. 构建 payload（主进程自己拿所有字段，不依赖渲染层）
        var gameMeta = mainGetGameMeta(gid); // 从 userData/game-meta.json 或拉服务端
        var payload = {
            gameId: gid,
            username: auth.username,
            installDir: libInfo ? libInfo.install_path : '',
            launchExe: r.exe,
            args: mainBuildLaunchArgs(reg, gid, auth, gameMeta), // 占位符替换 {0}{1}
            portForwards: gameMeta.portForwards || [],           // 管理端配置
            gateway: mainGetGateway(),                           // 从 userData/gateway.json 读
            steamEmu: gameMeta.steam_emu ? 1 : 0,
            steamAppId: gameMeta.steam_app_id || '',
            credential: auth.credential || '',                  // 账号专属凭证
            persona: auth.nickname || auth.username,
            netMode: gameMeta.net_mode || ''
        };

        // 4. 调 gameLaunch 内部函数（就是 game:launch IPC handler 的函数体，直接调不走 IPC）
        await mainInternalGameLaunch(payload);
        // ↑ 内部完整链路：fwEnsureForLaunch → gameForward.start →
        //   spawnSteamEmuGame / spawnGameChild → gameOverlay.onGameStart →
        //   waitGameWindowVisible → exit/error 清理监听
    } catch (e) {
        mainLog('[silent-launch] 异常: ' + (e && e.message));
    }
}
```

## 十、边界情况与异常处理

| 场景 | 处理方式 |
|------|---------|
| 游戏名含非法字符 `\/:*?"<>|` | C 层 sanitizeName 过滤为 `_`，返回 JSON 中 warn 字段提示 |
| 桌面路径无写入权限（公司策略） | IShellLinkW Save 失败返回错误码，C 层包装成可读中文 `{"ok":false,"error":"无法写入桌面"}` |
| shortcut-helper.exe 缺失 | main.js IPC 入口检查 fs.existsSync，返回 `{ok:false, error:'快捷方式辅助工具缺失'}` |
| 快捷方式已存在且非本程序创建 | 检查 TargetPath 是否指向 im-client.exe，是则覆盖（--overwrite），否则拒绝并提示 |
| SmartSteamEmu 单实例冲突 | 双击快捷方式启动游戏时同样受现有 `sseBusy` 互斥保护（game:launch 逻辑内已处理） |
| 用户卸载游戏后桌面快捷方式残留 | 快捷方式指向的是 im-client.exe（不是游戏 exe），卸载游戏后双击仍会打开客户端，但客户端会提示游戏未安装——与 Steam 卸载后快捷方式行为一致 |
| 已运行实例收到 second-instance 时窗口最小化 | **静默启动游戏**，mainWindow 保持最小化不弹出来（见 5.4 节行为矩阵） |
| 已运行实例在托盘时收到 second-instance | **静默启动游戏**，托盘图标保持不变，游戏进程被拉起 |
| 静默启动时未登录（auth.json 为空） | 主进程不弹窗、不打扰，只记 mainLog 一行日志，游戏不启动 |
| 静默启动时 exe 不存在 / needExe | 静默失败，不弹"手动选择主程序"对话框 |

## 附录 B：为什么选 C 而不是其他方案

| 方案 | 系统组件 | 可能被禁用 | 体积 | 依赖 |
|------|---------|-----------|------|------|
| PowerShell WScript.Shell | PowerShell 5 + COM + ExecutionPolicy | ⚠️ 组策略可禁用 | 0KB 但依赖 PowerShell | PowerShell 运行时 |
| VBScript .vbs | Windows Script Host | ⚠️ 组策略可禁用 | ~1KB 脚本 | WSH 运行时 |
| Python win32com | Python + pywin32 | ✅ 可控 | 50MB+ | Python + pywin32 |
| **纯 C IShellLinkW** | Windows Shell | ✅ 不可能被禁用（系统核心组件） | **~80KB** | **零** |

# 网关开发文档：Web 后台 + 游戏账号写入数据库（已拍板·P1 实施中）

> 状态：**已拍板**（2026-10-23 四项决策确认：① 队列按网关过滤 ② 密码明文比对 ③ 后台仅监听 127.0.0.1 ④ credential 预留不做，P1 仅 `{user}`+`{password}`）
> 关联文档：[端口透传功能使用说明.md](端口透传功能使用说明.md)（已上线部分的部署/使用）
> 涉及代码：`im-server/gateway/main.go`（网关）、`im-server/server/`（队列与拉取接口）、`im-server/gwproto/`（拉取协议共享包）、PC 客户端零改动

## 1. 需求背景

游戏服务端（网关后面的真实服务端）的用户体系存放在游戏自己的数据库中，老服务端通常**只读库验证、不自建账号**——玩家首次联机前需要有人把「IM 账号 + 启动密码 + 游戏凭证」预先写入游戏库，才能登录成功。

本期目标：

1. 给 im-gateway 增加 **Web 管理后台**：浏览器登录后可编辑监听组白名单、配置数据库写入，查看运行状态；
2. 建立**游戏账号自动写入**链路：玩家在 IM 侧登录后，服务端把 `{账号, 启动密码}` 经网关参数化写入游戏库（支持 INSERT / UPDATE）；
3. 数据库类型支持 **MySQL / MSSQL**（P1，均为纯 Go 驱动保持单二进制零依赖）；PostgreSQL / SQLite 预留 P2。

## 2. 关键架构决策：服务端发送 + 网关拉取（已确认）

凭证由 **im-server 服务端**产生与下发，**PC 客户端零参与、零改动**；传输方向为**网关主动向 im-server 拉取**（而非 im-server 推送）。

### 2.1 为什么服务端发而不是客户端发

| 维度 | ❌ 客户端发（隧道首帧附带） | ✅ 服务端发（拉模式） |
|---|---|---|
| 写入时序 | 启动游戏瞬间才写，DB 慢时与游戏首连有竞态 | **登录时就写好**，玩家启动游戏前账号必然已在库 |
| 信任面 | 持 token 的客户端可让网关写任意 user/password 组合（可覆盖他人账号密码） | 写入内容完全由服务端决定，网关不信任客户端任何写库请求 |
| 客户端改动 | 转发器首帧 + 启动 payload | **零改动** |
| 可靠性 | 客户端崩溃即丢 | 服务端队列持久化，网关不可达自动重试 |

### 2.2 为什么网关"拉"而不是 im-server"推"

- 拉：网关只需**出站**访问 im-server 现有 2087 端口——**零新增入站暴露面**；
- 推：im-server 必须连到网关的入站管理口（公网暴露 + 额外鉴权）；
- 写库不要求实时（登录后写入、玩家稍后启动游戏，30s 轮询延迟无碍）。

```
im-server                              im-gateway                        游戏库
─────────                              ──────────                        ──────
登录成功/密码派生 ──> 待写队列表(持久)
                          ▲ 拉取待写列表(HMAC鉴权, 30s周期)
                          ├──────────────────────────────> 参数化执行 SQL 模板 ──> INSERT/UPDATE
                          ◀──────────────────────────────  回执已写（按网关名区分）
```

## 3. 各角色设计

### 3.1 im-server（队列 + 拉取接口）

**待写队列表** `im_gateway_dbwrite`（持久化，重启不丢；uniqueIndex(username, game_id) 幂等）：

| 字段 | 说明 |
|---|---|
| id | 自增主键 |
| username | IM 账号 |
| game_id | 游戏 ID（队列按网关过滤的关联键：游戏转发规则里的 @网关名 决定哪台网关来拉） |
| password | 启动密码（launch_secret HMAC 派生，同账号恒定） |
| create_time / update_time | 入队/刷新时间 |

（`credential` 游戏凭证列 P1 不建——已拍板预留，将来启用时 AutoMigrate 自动加列）

**回执表** `im_gateway_dbwrite_ack`：`(dbwrite_id, gateway_name)` 唯一——每个启用写入的网关各自写各自的库、各自回执；"待写"判定 = 该网关无对应回执。

**触发点**（任一发生即入队/刷新条目；入队仅收**带网关模式转发规则的游戏**——纯单机/直连游戏无写库意义）：
- 玩家登录成功（finishLogin 异步顺带：该玩家库内全部含网关规则的游戏入队，不阻塞登录链路）；
- 启动密码派生/变更时（下次登录/心跳自然刷新，同账号幂等）；
- `game/play/start` 启动心跳（兜底补写当前游戏）。

同一账号同一游戏重复触发 → 更新队列中 password（内容不变则不动），保证幂等。

**内部拉取接口**（挂在 2087；协议实现归口 `im-server/gwproto/` 共享包，服务端与网关单实现零漂移）：

```
GET  /internal/gateway/dbwrite?gw={name}   # 网关自报身份拉取：返回该网关关联游戏的全部待写条目
POST /internal/gateway/dbwrite/ack         # 网关回执：{ids: [...]}，标记已写
```

- 网关身份：`gw` 自报 + **按条目专属密钥验签**（逐网关独立密钥，2026-10-23 拍板）——条目配置了专属 secret 时，HMAC 签名通过即密码学证明网关身份（不再仅自报家门）；未配置条目回退共享 gateway_token_secret（兼容存量，按地址簿存在性把关）。冒充他人网关名=用错密钥=验签必败；
- **按网关过滤**（已拍板）：im-server 解析全部游戏，两条命中路径取并集——① `port_forwards` 中 `mode=gateway` 且（`gw` 字段==网关名，或 `gw` 空==地址簿第一条启用网关）；② 游戏的 `dbwrite_gw` 字段==网关名（**仅写库游戏**：不配转发规则、显式声明写库归属——玩家客户端直连服务器无隧道）。游戏 A 的库不会混入只玩游戏 B 的玩家；
- 鉴权：**HMAC 签名头** `X-GW-Auth: {ts}.{hex(HMAC-SHA256(token_secret, ts+method+RequestURI+"."+hex(SHA256(body))))}`——**body 纳入签名**（GET 用空串哈希；POST /ack 的 `{ids}` 被中间人篡改即验签失败），时间戳 ±300s 防重放；签名不在线上传输 token_secret 本体（2087 可能明文 HTTP）；
- **响应体加密**（补强项）：拉取响应体 AES-256-GCM 加密——密钥 = `SHA256(token_secret + "|dbwrite-resp")`，随机 12B nonce 前置于密文，base64 承载，响应头 `X-GW-Enc: v1` 标记；网关无此头或解密失败即拒收——明文 HTTP 链路上中间人抓包看不到账号/启动密码；
- 仅返回**启用 dbwrite 的网关**可拉的内容；无 dbwrite 网关部署时接口数据为空，零开销。

### 3.2 im-gateway（后台 + 拉取器 + 写库执行器）

**Web 后台**（新 HTTP 端口，gateway.yaml 配置）：

| 配置 | 说明 |
|---|---|
| `admin_listen` | 后台监听地址，**默认 127.0.0.1:30101**（仅本机/内网访问；开放公网自担风险） |
| `admin_password` | 后台登录密码（启用后台必填，强密码），登录后发内存 session |

后台页面（HTML 内嵌单二进制，无需额外文件）：

1. **登录页**；
2. **总览**：各监听组的白名单、TCP 连接数、UDP 会话数、最近日志；
3. **白名单编辑**：每组 allow_targets 增删端口 → 内存即时生效 + 落盘 gateway.yaml（监听地址/端口类修改提示需重启）；
4. **数据库写入配置**：类型/DSN/「测试连接」按钮/INSERT 模板/UPDATE 模板/执行策略 → **在线编辑保存即热生效（P2 项已提前落地）**——服务端完整校验（非法拒绝保存不破坏运行中配置）→ 连接池重建/模板重编译 → gateway.yaml 落盘；换库/换表/换字段=直接改模板文本（支持全限定名 库名.表名）；
5. **写入状态**：最近 N 条写入成功/失败记录、队列积压数。

**拉取器**：30s 周期（可配 `poll_sec`）调 im-server 拉取接口（自报 `gw` 名）→ 校验 `X-GW-Enc` 头并解密响应 → 逐条执行写库 → 成功回执。**拉取失败/写库失败静默保留**（不回执 = im-server 侧下次仍返回，天然重试），网关侧不额外做重试队列。

**写库执行器**：

- 启动时/配置变更时按 `type` 建对应驱动连接池；
- 收到条目先算 `(username + password)` 摘要，与本地最近写入缓存比对——**相同内容跳过**（游戏多条隧道/重复登录不产生重复写）；
- 按策略执行：`insert`（只执行 INSERT 模板）/ `update`（只执行 UPDATE 模板）/ `upsert`（先 UPDATE，RowsAffected==0 再 INSERT）；
- **异步执行**，绝不阻塞游戏数据转发。

### 3.3 凭证来源（im-server 侧，全部现成）

| 占位符 | 来源 | 说明 |
|---|---|---|
| `{user}` | IM 账号名 | 玩家登录账号 |
| `{password}` | 启动密码 | 按游戏专属密钥派生（im_game.game_secret 每游戏独立持钥，同账号同游戏恒定，游戏启动参数 {1} 同源；已拍板明文比对——游戏服务端直接以此校验） |
| `{credential}` | 游戏凭证 | **P1 预留不启用**（已拍板：游戏库暂无此列需求；将来启用时队列/接口/模板同步放开） |

## 4. SQL 模板规范（注入防护核心）

管理员在网关后台填写模板，占位符**编译为数据库参数绑定**，绝不字符串拼接：

```
模板:  INSERT INTO members(account, password) VALUES({user}, {password})
执行:  INSERT INTO members(account, password) VALUES(?, ?, ?)     args=[plb789, 3847798341565109]
```

（占位符按驱动方言转为 `?` / `@p1` / `$1`）

**模板校验（保存时拦截）**：

| 规则 | 说明 |
|---|---|
| 语句类型白名单 | 仅允许 `INSERT` / `UPDATE` / `MERGE`（MSSQL、PG15+）/ `CALL`·`EXEC`·`EXECUTE`（存储过程调用）开头；DELETE/DROP/TRUNCATE/ALTER/CREATE/SELECT 一律拒绝。**复杂多表+事务逻辑建议写游戏库端存储过程，网关模板只带参调用（安全模型不变）**；merge/call/exec 类模板自带全语义，无论 strategy 均单次执行（不参与 upsert 组合，防重复写） |
| 禁止多语句 | 模板中出现 `;` 拒绝（尾分号除外） |
| 禁止注释 | `--` 与 `/*` 出现即拒绝（防注释逃逸） |
| 占位符合法性 | 仅 `{user}` `{password}`（`{credential}` 预留暂不启用），未知占位符拒绝 |

**输入约束（双保险）**：username 服务端本就限字符集；password 为 16 位纯数字派生——两者均不可注入，叠加参数绑定后风险归零。

## 5. 数据库支持矩阵（全部纯 Go、零 CGO、单二进制不变）

| 类型 | 驱动 | 参数方言 | 状态 |
|---|---|---|---|
| MySQL | go-sql-driver/mysql | `?` | **已实施**（im-server 既有依赖） |
| MSSQL | microsoft/go-mssqldb（注册名 sqlserver） | `@p1` | **已实施**（驱动名映射 dbwriteDriverName——注册名非 mssql，直开会 unknown driver panic） |
| PostgreSQL | jackc/pgx v5 stdlib（注册名 pgx） | `$1` | **已实施（P2 提前落地）** |
| SQLite | modernc.org/sqlite（纯 Go 零 CGO） | `?` | **已实施（P2 提前落地）** |
| Oracle | godror 需 CGO + Instant Client | — | **不做**（破坏单文件部署，确需再评估） |

- 网关与 im-server 共用 go.mod，Go 按需链接——im-server 二进制体积不受影响；
- 四类型执行层验证：SQLite 真实写库全链路测试（零外部依赖必跑）+ MySQL 集成测试；postgres/mssql 由方言编译测试与驱动名映射覆盖（部署后「测试连接」按钮可现场验证）。

## 6. gateway.yaml 新增配置节

```yaml
# ===== Web 管理后台（可选；不填则不启动后台） =====
admin_listen: "127.0.0.1:30101"   # 后台监听（默认仅本机/内网；开放公网自担风险）
admin_password: "后台登录强密码"     # 启用后台必填

# ===== 游戏账号写入（可选；不启用则拉取器不启动） =====
dbwrite:
  enabled: true
  gateway_name: "gw-x"                   # 自报网关名（须与 im-server 地址簿条目名一致，拉取时 ?gw= 传给服务端做按网关过滤）
  im_addr: "http://im-server地址:2087"  # im-server 拉取地址（响应体经 AES-GCM 加密，明文链路不泄密）
  type: mysql                            # mysql / mssql（P1）；postgres / sqlite（P2）
  dsn: "user:pass@tcp(127.0.0.1:3306)/gamedb"
  strategy: upsert                       # insert / update / upsert
  poll_sec: 30                           # 拉取周期（默认 30s）
  sql_insert: "INSERT INTO members(account, password) VALUES({user}, {password})"
  sql_update: "UPDATE members SET password={password} WHERE account={user}"
```

- `token_secret` 复用现有配置（拉取接口 HMAC 鉴权密钥），不新增密钥；
- 后台编辑白名单/DB 配置后**落盘 gateway.yaml + 内存热生效**（DSN 变更重建连接池）。

## 7. 安全设计汇总

| 项 | 措施 |
|---|---|
| 拉取接口鉴权 | HMAC-SHA256(token_secret, ts+method+RequestURI+body哈希) 签名 + 时间戳 ±300s 防重放；**body 纳入签名**（ack 的 ids 不可被中间人篡改）；不在线传密钥本体 |
| 拉取响应加密 | 响应体 AES-256-GCM（密钥由 token_secret 派生 + 随机 nonce，`X-GW-Enc: v1`）——明文 HTTP 链路中间人抓包看不到账号/启动密码（**安全补强项，已实施**） |
| 网关身份 | **逐网关独立密钥**（im_gateway_book.secret）：条目专属验签密钥泄露/轮换半径=单网关；写库拉取/隧道 token 均按条目密钥签发与验证，签名通过=身份密码学证明；空条目回退共享 gateway_token_secret |
| SQL 注入 | 占位符→参数绑定（强制）；模板语句类型/多语句/注释白名单校验；输入字符集约束（账号限字符集 + 密码 16 位纯数字）双保险 |
| 后台鉴权 | admin_password 登录 + 内存 session；**仅绑 127.0.0.1（已拍板）**，远程走 SSH 隧道 |
| 凭证泄露面 | 队列仅服务端 DB（服务端本就持有）+ 传输中密文；网关**不落日志**（凭证打码）不落盘；只写目标库 |
| 密钥泄露兜底 | 启动密码按**每游戏独立密钥**派生（im_game.game_secret）：单游戏密钥泄露/轮换半径=该游戏——更换该游戏 game_secret → 该游戏队列密码重派生 → 网关自动重写该游戏库，**其他游戏零感知**；全局 launch_secret 仅作补种失败兜底 |
| 游戏转发不受影响 | 写库异步执行；DB 不可达仅影响账号写入，游戏隧道转发完全独立 |
| 既有隧道安全 | 不变：TLS 1.3 + 证书 pin + token 短效 + 白名单 |

## 9. 验收清单（P1）

- [ ] 玩家登录后 im-server 队列出现该账号条目（仅含网关规则的游戏）；重复登录不产生重复行
- [ ] 网关 30s 内拉取（响应密文解密成功）并写入游戏库；INSERT / UPDATE / upsert 三策略各自生效
- [ ] 按网关过滤：gw-x 拉不到仅关联 gw-y 的游戏条目；@缺省规则关联地址簿第一条启用网关
- [ ] 模板含 DELETE/分号/注释/未知占位符 → 启动/配置加载即拒绝
- [ ] 密码含特殊字符场景（参数绑定下）写入内容逐字正确
- [ ] 网关写库失败（停库）→ 不回执 → im-server 侧保持待写 → 恢复后自动补写
- [ ] 明文链路抓包：拉取响应内容不可见（AES-GCM 生效）；篡改 ack body / 过期签名 / 无签名 → 401
- [ ] 游戏数据转发全程不受写库影响（写库耗时/失败均不阻塞隧道）
- [ ] 网关重启不丢配置（落盘）；im-server 重启不丢队列（持久表）
- [ ] 后台未登录访问任意页面 401；后台仅 127.0.0.1 可达
- [ ] 客户端与 im-server 常规功能回归无影响（客户端零改动）

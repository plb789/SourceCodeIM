# 会议入口下拉改造与会议号加入（阶段一百五十二）

## Context

用户需求：
1. 群「发起会议」单一入口改成「创建会议 / 加入会议」两个入口；工具栏会议图标旁加小三角（同截图按钮 `shot-caret` 样式），点开下拉菜单选择。
2. **创建会议：创建人直接进入会议等待**，不弹选人弹窗；进会后通过会议窗现有「邀请成员」按钮（会中追加邀请链路 `meetInviteMore`，信令复用 `meet_invite`，meet.go L129-134）再次邀请他人加入。
3. 加入会议：输入 9 位会议号加入进行中的会议。

现状约束：call_id 由客户端生成（长串不适合手动输入）→ 引入**服务端生成的 9 位数字会议号（MeetNo）**，建房时分配、会议窗展示可复制、join 按号查房。现有 `meet_invite` 的 members 为空即「创建等待模式」——需处理 60s 响铃超时误杀（见下）。

## 服务端改动（im-server）

### call.go
- `HandleCallSignal` switch（L78-117）新增：`case "meet_join_no": s.handleMeetJoinNo(from, msg, &p)`

### meet.go
1. **meetRoom 结构体（L41-65）** 加 `MeetNo string`。
2. **handleMeetInvite（L111-245）两处改动**：
   - **创建等待模式（members 为空）**：跳过成员校验循环（现空转天然兼容），建房后**置 `room.Started = now` 且不起 ringTimer**——创建人已入会即会议成立，防 60s `missed` 超时把等待中的会议误解散（ringTimeout 守卫见 Started 非零即空转）。members 非空的现有邀请模式逻辑不动。
   - 建房成功后生成 9 位纯数字会议号（`100000000+rand`），遍历 meetRooms 查重、冲突重试（最多 5 次），存 `room.MeetNo`。
3. **新增 `handleMeetJoinNo`**（上行 `{action:'meet_join_no', meet_no}`），流程参照 handleMeetAccept：
   - 按 MeetNo 查房 → 不存在：`callSendError(from, ...,"会议不存在或已结束")`
   - 校验：设备能力 `hub.HasCall` 不满足 → error「当前设备不支持」；`callUserBusy[from]` 已忙 → error「你正在通话中」；已是成员 → error「你已在会议中」
   - 写锁升级：加入 `Members`、从 `Invited` 剔除（若在）、设 `callUserBusy[from]=room.ID`、停 ringTimer + 置 Started（响铃期 join 即会议成立）
   - 解锁后：广播既有 `meet_join` 帧（其余成员会议窗自动加 tile，帧格式不变）；给 joiner 发 `room_info`（含 call_id、meet_no、call_type、group_id、members、群信息，结构对齐 accept 下发）；按快照补发 `meet_share` / `meet_media`（复用阶段一百五十一补发机制）
4. **room_info / meet_join 下行帧构造点**补 `meet_no` 字段。

## 客户端改动（im-client/web）

### index.html
- `meet-btn`（L419-421）内加 `<span class="meet-caret">`（同 `shot-caret` 结构样式）；title 改「会议」
- 下拉菜单 DOM（绝对定位小面板，自绘、跟随主题变量）：「创建会议」「加入会议」两项，默认 hidden

### chat.js
- `meet-caret` 点击切换菜单显隐；点击其他区域关闭（参照截图菜单外部关闭逻辑）
- 菜单「创建会议」→ 直接 `startMeet('video', [])`：不弹选人、立即开会议窗进会等待（视频会议，会内可用现有摄像头按钮关闭）；邀请他人走会议窗现有「邀请成员」按钮
- 菜单「加入会议」→ `showPrompt('加入会议', '请输入 9 位会议号', val => { 校验纯数字9位; callSignalSend('', {action:'meet_join_no', meet_no: val}) })`；发前置检查同 startMeet（callOpenId/pendingRing 提示）
- 收到 `room_info`（joiner 场景）→ 复用 accept 分支逻辑 `callOpen({role:'callee', meet:true, call_id, meet_no, call_type, group_id, meet_title, ...})` 开会议窗
- `error` 帧 → 现有 toast 链路提示（「会议不存在或已结束」等）

### call-page.js + call-window.html
- `meetInit` 接收并存 `st.meetNo`
- 会议窗顶部（meetTop 群名旁）显示「会议号 123456789」+ 复制小图标（自绘、跟随主题色），点击复制（PC 走现有剪贴板桥 / WEB `navigator.clipboard`，失败 toast）

### 手机端
- 会议一期不支持手机端，工具栏入口本就 hidden，无影响

## 验证

1. 编译：go build / go test ./server/；node --check chat.js / call-page.js / web-call-bridge.js；改动文件 UTF-8 无 BOM
2. 实测（双账号）：
   - A 下拉「创建会议」→ 不弹选人，A 直接进会议窗；会议窗顶部显示 9 位会议号，点击可复制
   - A 在会内等待 >60s **不被 missed 解散**（创建等待模式核心回归点）
   - A 点会议窗「邀请成员」→ 选人弹窗 → B 响铃 accept 加入 → 正常
   - B 输入会议号加入 → 直接进会；A 端 B 的 tile 自动出现；共享/设备状态快照补发正确
   - B 退出 → 忙标记清除、A 端 tile 移除；A 等待中直接退出（空会）→ 解散无残留
   - 错误分支：错误会议号 / 自己正忙 / 重复加入 → toast 文案正确
   - 响铃期（A 邀请 B 未接时）C 用会议号加入 → 会议成立，ringTimer 停表
   - 回归：60s 响铃超时（正常邀请模式仍生效）、追加邀请、离线宽限、1v1 通话

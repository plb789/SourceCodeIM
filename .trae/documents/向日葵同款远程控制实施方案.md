# 向日葵同款远程控制（设备ID + 验证码）实施方案

## Context（背景与目标）

用户希望在 PC 端和手机端增加"向日葵同款"远程控制：输入**设备ID + 验证码**即可直接控制对方电脑，无需像现在的远程协助那样由对方点击接受。

好消息是项目已具备绝大部分底层能力，本次是**扩展**而非新建：

- 现有"QQ 同款远程协助"（阶段一百五十五）已实现：被控端 `getDisplayMedia` 静默抓屏 → WebRTC 视频轨 P2P → 控制端观看窗捕获鼠标/键盘 → DataChannel 回传 → 主进程 PowerShell `SendInput` 注入。见 [remote-engine.js](file:///e:/SourceCodeIM/im-client/web/js/remote-engine.js)、[remote-page.js](file:///e:/SourceCodeIM/im-client/web/js/remote-page.js)、[remote-input.js](file:///e:/SourceCodeIM/im-client/pc/remote-input.js)、[remote.go](file:///e:/SourceCodeIM/im-server/server/remote.go)
- 服务端已内置 TURN/STUN 中继（阶段一百四十二，`turn.enabled: true`），且通话/文件P2P 已通过 [callInjectICE](file:///e:/SourceCodeIM/im-server/server/call.go#L171-L186) 下发 `iceServers`——但**远程协助引擎仍是 `RTCPeerConnection(null)` 纯 P2P，跨 NAT 连不通**，这是必补的缺口。

已确认的产品决策：
1. 手机端**仅作控制端**（手机被控、平板本期不做）
2. **验证码即授权、自动接通**，被控端不弹确认，仅显示悬浮提示条
3. 验证码**动态码 + 静态访问密码**双模式
4. **不限好友**，凭 ID+验证码即可连（配防爆破限速）
5. 与现有好友远程协助**并存**，旧流程零改动

## 关键设计决策

**设备ID 存服务端**（不放客户端本地）。新增表 `im_device`：`username / install_uuid / device_id(9-10位随机, uniqueIndex) / static_pw_hash / dyn_code / dyn_expire / device_name / last_seen`。客户端在 Electron `userData` 生成持久 `install_uuid`，登录时上报，服务端按 `(username, install_uuid)` 分配或复用 device_id——同机重装可找回原ID，同账号多台PC各自一行，对齐向日葵"一台设备一个ID"语义。

**验证码服务端生成与校验**（不放被控端，否则在线设备可被无限速爆破、离线设备无法区分）。动态码 6 位数字，`rc_connect` 时惰性刷新（过期即重生成，TTL 5 分钟），经 `rc_ready`/`rc_info` 推给被控端展示；静态密码由用户在面板设置 → HTTP 接口 → bcrypt 存 `static_pw_hash`（空=未启用）。防爆破：内存计数 `device_id→失败次数`，5 次锁 10 分钟，仿 [purge.go](file:///e:/SourceCodeIM/im-server/server/purge.go) 定时清理。

**信令复用 MsgTypeRemoteSignal=90，新增 action**：`rc_connect`（控制端上行 `{device_id, code}`）、`rc_ready`（服务端→被控端：自动接通，含 `session_id / grant=control / ice`）、`rc_error`。`offer/answer/candidate/disconnect` 全部复用。校验通过后服务端直接构造 `remoteSession{Mode:"rc", Grant:"control", State:active, AcceptAt:now}` 并占 `remoteUserBusy`，跳过 invite/accept 人工环节，复用现有话单落库、忙互斥、离线宽限。

**话单**：[RemoteLog](file:///e:/SourceCodeIM/im-server/model/model.go#L75-L92) 加列 `device_id`，`Mode` 新增取值 `"rc"` 区分两种模式（AutoMigrate 自动加列）。

## 风险与注意
- **隐私合规**：自动接通必须醒目悬浮条 + 被控端一键断开；建议提供"仅动态码时段可被控"开关
- **复用现有健壮逻辑**：offer 竞态缓冲 `pendingCands`、90s `connectTimer`、30s 看门狗、离线宽限——rc 流程直接复用，勿另起炉灶
- **TURN 带宽**：1080p/15fps 中继约 2-4Mbps/会话，注意 `max_port` 区间与并发上限
- **回归**：每次改动后需验证旧好友远程协助、音视频通话、文件P2P 不受影响（共用引擎与 TURN）

## 验证方式（端到端）
1. 阶段一：启动 im-server，登录两台 PC，查 `im_device` 表生成 device_id；`/api/rc/*` 返回正确；错误验证码触发锁定
2. 阶段二：PC-A 面板显示自身ID+动态码；PC-B 输入该ID+码 → PC-A 悬浮条出现"正在被控" → PC-B 观看窗实时看到 PC-A 桌面，鼠标键盘可操作 PC-A；断开后 `im_remote_log` 落 `Mode=rc` 话单
3. 阶段三：两台设备置于不同网段（一内网一4G），重复阶段二验证连通；观察是否走 relay（`chrome://webrtc-internals` 看 candidate 类型）
4. 阶段四：手机 APP 输入 PC 的 ID+码，手机全屏看到 PC 桌面，单指点击/双指滚动/虚拟键盘输入可用
5. 回归：旧好友协助邀请-接受流程、1v1 通话、文件 P2P 各跑一遍确认无影响

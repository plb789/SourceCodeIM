# 阶段一百五十三：会议窗内邀请成员面板（不再跳回聊天窗口）

## Context

当前会议窗「邀请成员」按钮经桥（`d.meetInviteAsk` → 主窗口 `openMeetPicker('invite')`）在**聊天主窗口**内打开选人弹窗——会议窗聚焦时点邀请，弹窗却开在后面被会议窗挡住，用户需来回切窗口，体验割裂。

目标：会议窗内直接弹出**独立的邀请面板**（搜索 + 成员列表 + 勾选 + 确认），与聊天窗口的选人弹窗彻底分开。数据走服务端归口（新增拉取信令），不依赖主窗口状态。

## 方案总览

```
会议窗 btnInvite → 打开内嵌面板 → send('meet_members_ask')（send 自动带 call_id）
  → 服务端 handleMeetMembersAsk：查房间 → 校验成员 → getGroupMemberIDs(group_id)
    → 逐人状态归口（在线/可通话/忙/已在会）→ 下行 meet_members_list
  → 会议窗 case 'meet_members_list' 渲染列表 → 勾选 → send('meet_invite',{members})
  → 服务端 meetInviteMore（现有追加邀请链路零改动）→ meet_skipped/room_info 反馈既有
```

chat.js **零改动**：`meet_members_list` 走信令分发通用中继（会议成员 callOpenId 已置位）；上行走 onCallSend → WS。

## 改动明细

### 1. 服务端 im-server/server/meet.go + call.go

**新增 `handleMeetMembersAsk`**（放在 handleMeetJoinNo 之后）：
- 解析 `{call_id}`（p.CallID）；`meetRoomOf` 不存在 → 下行 `meet_members_list{members:[]}` 静默兜底
  - **禁用 error 帧**：会议窗 error 分支会 finish 关窗，拉取失败不可误关窗
- 校验 `room.Members[from]`（非成员不给名单，同样走空列表兜底）
- `getGroupMemberIDs(room.GroupID)`（group.go L99 现成函数）取群成员
- 锁内快照 `Members/Invited`，锁外逐人构造（复用 `meetInfoOf` 昵称头像归口）：
  - `online`：`s.hub.Count(id) > 0`
  - `call_ok`：`s.hub.HasCall(id)`
  - `busy`：`callUserBusy` 有值
  - `in_meeting`：`room.Members[id] || room.Invited[id]`（前端置灰不可勾）
  - 排除自己
- 下行 `meet_members_list {call_id, members:[...]}` → `s.callForward(from, from, ...)`

**call.go** 加分发：`case "meet_members_ask": s.handleMeetMembersAsk(from, msg, &p)`

### 2. 会议窗 call-window.html

- 新增面板 DOM：`#inviteMask`（遮罩）+ `#invitePanel`（标题「邀请成员」+ 关闭钮、搜索输入框、`#inviteList` 成员列表、底部已选计数 + 取消/邀请按钮）
- 样式：会议窗深色风格（遮罩 rgba、面板 #22262b 圆角、主题绿高亮选中项）；滚动条复用 L251-288 meet-side 的 `::-webkit-scrollbar` 自绘样式（禁系统默认）
- 成员行：头像（服务端 avatar，空降级首字母）+ 昵称 + 状态徽标（可邀/忙/会议中/离线/设备不支持）+ 右侧勾选框（in_meeting/busy/离线/不支持置灰）

### 3. call-page.js

- `btnInvite` 点击改为 `openInvitePanel()`（不再 `d.meetInviteAsk`）：清空旧数据 → 显示面板加载态 → `send('meet_members_ask', {})`
- `meetOnSignal` 加 `case 'meet_members_list'`：面板开着才渲染；空列表显示「暂无可邀请的成员」（查无数据显示暂无，不用"加载失败"）
- 搜索框本地过滤（昵称/账号）；勾选集合联动底部计数与邀请按钮可用态
- 「邀请」→ `send('meet_invite', {call_type: st.callType, group_id: st.groupId, members: selected})` → 关面板 → `setMeetStatus('邀请已发送，等待成员加入…')`；拒绝/跳过反馈走既有 `meet_skipped` 分支
- Esc 处理：在会议窗现有 Esc（退出全屏）keydown 入口前置判断——面板开着先关面板
- 关面板兜底：会议结束 finish 时同步关面板

### 4. 旧链路处置

`d.meetInviteAsk` 桥链路（preload.js L559-568 / main.js / web-call-bridge.js / chat.js onMeetInviteAsk / openMeetPicker('invite') 分支）不再被触发。**本次保留不删**（基础设施无害，减少改动面），计划中备案。

## 验证清单

1. 创建会议（等待模式）→ 会议窗点「邀请成员」→ 面板在**会议窗内**弹出，列表含全群成员与状态
2. 勾选成员邀请 → 对方响铃 → 接入后宫格增量建连正常（复用 meetInviteMore 全链路）
3. 拒绝/忙/离线成员 → meet_skipped 状态栏提示正常
4. 已在会成员在列表中显示「会议中」置灰不可勾
5. Esc / 关闭钮 / 邀请成功 → 面板关闭；会议结束面板同步关闭
6. 回归：主窗口群工具栏原选人发起（主区域点击）不受影响；WEB 端 iframe 会议窗同样可用
7. 性能：列表拉取为单次信令查询（低频路径），面板关闭即释放，无常驻开销

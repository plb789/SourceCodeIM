# 后台来电拉起接听画面 — 实现方案（阶段二百三十七）

## Context

APP 切后台后 WebView 被冻结，通话邀请（`msg_type=70, action=invite`）由原生 `KeepAliveService` 接管连接收到，但当前只弹普通文字通知（`showMsgNotice`），无法展示接听画面——渲染代码在冻结的 WebView 里跑不了，且 Android 10+ 禁止后台直接启动 Activity。微信的解法是 Android 为来电类应用专设的「全屏意图通知 + 悬浮窗权限」组合：熄屏/锁屏时全屏拉起来电界面，亮屏使用中时横幅置顶（或悬浮窗直接盖屏弹出）。

## 实现策略（三级降级，与微信实际行为一致）

KeepAliveService 后台收到 `action=invite` 时按权限分级：

1. **有悬浮窗权限**（`SYSTEM_ALERT_WINDOW` 已授权）→ 原生直接 `startActivity` 拉起 MainActivity（后台启动豁免），带来电参数，不弹通知
2. **无悬浮窗但有全屏意图**（`USE_FULL_SCREEN_INTENT`）→ 发**全屏意图通知**（新 CH_CALL 渠道，来电铃声+振动）：
   - 熄屏/锁屏：系统自动全屏拉起接听页
   - 亮屏使用中：heads-up 横幅，点击进入接听页
3. **都没有** → 维持现状普通通知

拉起 MainActivity 的载体统一用 deep-link `imapp://call?from=<caller>&type=<voice|video>&call_id=<id>&meet=<0|1>`，复用现有 `imapp://chat?to=` 同款通道。

## 改动文件

### 原生（Android）

1. **KeepAliveService.java**
   - `handleFrame()` 的 `msg_type=70 && action=invite` 分支改造：调新方法 `showCallInvite(json)` 替代普通通知
   - 新增 `showCallInvite()`：
     - 新建 `CH_CALL` 通知渠道（`CHANNEL_CATEGORY_CALL` + 来电铃声 loop + 振动，仿照现有 `ensureChannels()`）
     - 组装 deep-link `imapp://call?...`（参数从 invite 帧取：from_user/call_id/call_type/meet）
     - PendingIntent：`Intent(ACTION_VIEW, uri, this, MainActivity.class)` + `FLAG_IMMUTABLE`，`setFullScreenIntent` + `setContentIntent` 双挂
     - 有 `SYSTEM_ALERT_WINDOW` 时直接 `startActivity` 拉起（Settings.canDrawOverlays 判断）
     - 记录当前来电通知 ID 与 call_id
   - 收到 `action=cancel/reject/timeout`（同 call_id）→ `NotificationManager.cancel()` 撤掉来电通知
2. **AndroidManifest.xml**：加 `<uses-permission android:name="android.permission.USE_FULL_SCREEN_INTENT" />`（SYSTEM_ALERT_WINDOW 无需声明，走设置页授权）

3. **BackgroundIMPlugin.java**（仿照 L235-317 保活引导模式）
   - `getCallAlertStatus`：返回 `{fullScreen: 是否可全屏, overlay: canDrawOverlays()}`
   - `openFullScreenIntentSettings`：跳 `Settings.ACTION_MANAGE_APP_USE_FULL_SCREEN_INTENT`（Android 14+；低版本降级应用详情页）
   - `openOverlaySettings`：跳 `Settings.ACTION_MANAGE_OVERLAY_PERMISSION?package=`

### 前端（web，三端共用）

4. **chat.js**（L458-481 附近，仿照现有 imapp://chat 路由）
   - `handleUrl` 扩展识别 `imapp://call` → 解析参数 → 调 `window.desktop.callRing({call_id, call_type, caller, meet, ...})`（web-call-bridge.js L307 `showRing`，必需字段 call_id/call_type/caller）展示接听画面
   - 后续接听/拒绝走现有 `onCallRingAction` → `callSignalSend` 链路，无需改动
5. **设置页引导**（index.html + 设置 js，仿照「后台保活」引导 UI）
   - 新增「来电弹窗」引导项：调 `getCallAlertStatus` 判定状态，跳转/引导开启全屏意图与悬浮窗权限（沿用现有自绘弹窗风格）

## 注意点

- **信令不落库**：invite 是实时帧，WebView 重连后不会重收——接听画面数据完全来自 deep-link 参数，accept 信令靠 call_id 对上
- **竞态安全**：拉起后 WebView 恢复走现有 `bgEndHandover` 重连 + `handBack`，原生断开，无新互踢面（阶段二百三十五防重入已覆盖）
- 普通消息通知行为不变；仅 invite 分支升级
- 本地服务端改动：无（纯客户端功能）

## 验证

1. `gradlew assembleDebug` 编译 APK 安装 MuMu，连本地服务器
2. 账号 A（MuMu APP）切后台 → 网页端账号 B 发起语音通话：
   - 熄屏：应自动亮屏全屏弹出接听画面
   - 亮屏停在桌面：横幅通知点击进接听画面
   - 授予悬浮窗权限后：亮屏直接弹出接听画面（无需点通知）
3. 接听 → 进入通话窗、双向音频正常；拒绝 → 对方收 decline；B 取消 → A 的来电通知自动消失
4. 回归：后台普通消息通知（文案/点击进会话）不受影响；前台收到邀请仍走现有 WebView 响铃条
5. Android 14 模拟器/真机验证全屏意图权限引导流程（默认收回场景）
